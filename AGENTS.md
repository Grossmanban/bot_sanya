# Правила для ИИ-агента в этом репозитории

Проект «Иди работай!»: Telegram-бот + Mini App для графика смен. Отвечать заказчику по-русски, интерфейс — на русском.
Подробное описание функций — README.md, история решений — docs/. Текущее задание — docs/tz-28.10.md.

## Стек и устройство
- Один процесс: aiogram 3 (бот, long polling) + FastAPI (API Mini App) + встроенный планировщик (backend/app/jobs.py).
- SQLite (WAL). Схема — список `MIGRATIONS` в backend/app/db.py, только дописывать новые в конец, старые не менять.
  Важно: `_run_script` делит SQL по `;` — не ставить `;` внутри SQL-комментариев.
- Mini App: Next.js (static export) + shadcn/ui, frontend/src. Собирается в frontend/out, отдаётся бэкендом.
- Docker: Dockerfile + docker-compose.yml + Caddy (HTTPS). База и медиа в томе ./data → /data.

## Где что лежит (перед новой системой — найти существующую и доработать её)
- Права и роли (owner / admin / instructor / trainer / employee): backend/app/permissions.py — единственное место правил.
- Приглашения, реферальные ссылки, QR: invites.py. Онбординг и кандидаты: recruiting.py.
- Группы «Предзакреп» / «Основная команда»: groups.py. Доступ к продуктам «Работа»: products.py.
- «Алиса» (выполнения, фото, публикация в форум, модерация, сверка с Яндексом): alice.py.
- Деньги: finance.py (журнал штрафов/бонусов/вычетов), payouts.py (реквизиты СБП, реестр и мастер выплат),
  rates.py / pricing.py (ставки, налог на лень).
- Уведомления и ссылки на профили: notify.py. Рассылки: broadcasts.py. Шаблоны и настройки: app_settings.py.
- Бизнес-правила смен: services.py (каждая мутация — одна транзакция, идемпотентность по ключу).

## Проверки (запускать перед каждым коммитом и честно сообщать результат)
```bash
# бэкенд, один раз:
python3 -m venv .venv && .venv/bin/pip install -q -r backend/requirements-dev.txt
# тесты:
cd backend && ../.venv/bin/pytest -q
# фронтенд (нужен Node 22):
cd frontend && npm ci && npm run lint && npm run build
# если Node нет — собрать образ целиком, это тоже проверяет сборку фронтенда:
docker build -t bot_sanya_dev .
```
Новая логика — новые тесты в backend/tests (по образцу соседних файлов).

## Жёсткие запреты
- Рабочая копия для разработки — ЭТА папка. Боевая установка — /opt/bot_sanya: её файлы, .env, data/ и контейнеры
  не трогать вообще. Не запускать `docker compose` в /opt/bot_sanya и не останавливать боевого бота.
- Никогда не коммитить и не выводить секреты: токен бота, ADMIN_IDS, токены GitHub/DuckDNS, ключи API.
  Они живут только в /opt/bot_sanya/.env.
- Не переписывать историю git (никаких force-push, rebase опубликованных коммитов).
- Не реализовывать накрутку/фейковые отзывы от имени сотрудников (ТЗ «ReviewFlow») — это отклонено.
- Если требование противоречит текущей логике или неоднозначно — остановиться и спросить заказчика.

## Git и выкладка
- Рабочая ветка `claude/schedule-bot-miniapp`; `main` держать равной ей.
- Коммит — после зелёных тестов и сборки, сообщение по-русски, что изменилось для пользователя.
- Пуш: `git push origin claude/schedule-bot-miniapp && git push origin claude/schedule-bot-miniapp:main`
- Выкладка на боевой сервер — ТОЛЬКО когда заказчик прямо скажет «выкладывай»:
  `sudo bash /opt/bot_sanya/deploy/install.sh` (скачивает ветку, пересобирает, .env и база сохраняются).
