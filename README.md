# График смен — Telegram-бот + Mini App

Бот регистрирует сотрудников и шлёт уведомления админам. Mini App (веб-приложение внутри Telegram) — запись на смены, отмены, профиль, история и админ-панель.

Всё работает **одним процессом** на одной базе **SQLite**: бот (aiogram, long polling), API (FastAPI) и статика Mini App (Next.js + shadcn/ui, собирается в `frontend/out`).

```
backend/
  app/
    main.py       запуск: бот + API + статика в одном asyncio-процессе
    bot.py        /start, регистрация, «Принять/Отклонить», срочные заявки, штрафы, /raspred_zavtra
    api.py        REST API для Mini App (проверка подписи initData на каждый запрос)
    services.py   вся бизнес-логика: смены, отмены, восстановление, штрафы, статистика
    notify.py     тексты уведомлений и рассылка админам
    db.py         схема SQLite
    pricing.py    ставки: 120 ₽/шт., при объёме < 20 — 100 ₽/шт.
  scripts/backup.py   бэкап базы на ходу
  tests/              тесты логики и API
frontend/         Next.js 15 + shadcn/ui (статический экспорт)
```

## Как работает

| Где | Что |
|---|---|
| Бот | `/start` → «📝 Заполнить анкету» → анкета в Mini App (см. «Рекрутинг»). Админы получают анкету с фото профиля и ведут кандидата в «Админ → Онбординг»: обучение → стажировка → сотрудник. |
| Бот (админам) | Уведомления о записи, срочной заявке на сегодня (кнопки «Разрешить / Запретить»), отмене, восстановлении, изменении, сообщениях «Связаться с админом», отчётах и неявках (кнопки штрафа 1 / 3 / 5 единиц / своё число). Кнопка «📋 Распред на завтра» и `/raspred_zavtra` — простым текстом для копирования. |
| Mini App → График | Неделя пн–вс, карточки дней со статусами ❔ ✅ ⏳ 🚫 ❌ 🔒 ⛔, коллеги на день. В шторке дня: время «с–до», точка, объём (с предупреждением про «налог на лень» и планом заработка), «Выйду» / «Не выхожу в этот день». |
| Mini App → Профиль | Переключатель «Работаю / Не работаю» (без него запись закрыта), история смен, мои штрафы, ставки, тема оформления. |
| Mini App → Админ | Распред на завтра + «Скопировать», все смены на любой день, статистика сотрудника за период, журнал штрафов, ручная правка любой смены (с обязательной причиной). |

### Открыть приложение без чата с ботом

- **Один раз в @BotFather** (делает владелец бота): `/mybots` → бот → **Bot Settings** → **Configure Mini App** → **Enable Mini App** → прислать адрес Mini App (тот же, что `WEBAPP_URL`). После этого рядом с ботом в списке чатов, в поиске и в профиле бота появляется кнопка «Открыть», а ссылка `https://t.me/<бот>?startapp` открывает приложение сразу.
- **В приложении:** «Профиль» → «Быстрый доступ» → «Добавить на главный экран» — иконка на телефоне (Telegram 8.0+), инструкция для iPhone и личная ссылка `t.me/<бот>?startapp` — только для себя. Ниже — отдельная карточка «Пригласить человека на работу и получить денежный бонус» (ссылка-приглашение в «Мои рефералы»). Внутри чата приложение открывает кнопка меню «Приложение» (слева от поля ввода; до 29.10 называлась «График»).

### Тема оформления

По умолчанию приложение следует ночному режиму Telegram. Кнопка ☀️/🌙 в шапке (на телефоне) переключает светлую и тёмную тему одним касанием; в профиле и в боковой панели на компьютере есть выбор «Как в Telegram / Светлая / Тёмная». Выбор запоминается на устройстве.

### Роли

| Роль | Кто | Что может |
|---|---|---|
| Владелец | `ADMIN_IDS` в `.env` (можно несколько) | Всё: роли, блокировки, деньги, общий факт дня |
| Администратор | назначает владелец | Все сотрудники: смены, отчёты, штрафы, паузы, рассылки, настройки. Без денег и блокировок |
| Тренер | назначает владелец | Только своя сеть (включая людей инструкторов): смены, отчёты, паузы. Штрафы — через администратора |
| Инструктор | назначает владелец | Только закреплённые за ним сотрудники своей сети: смены, отчёты, паузы, личные и групповые цели, рассылки своим людям. Штрафы — через администратора |
| Сотрудник | после одобрения заявки | Свой график, отчёты, штрафы |

Пауза (с причиной) закрывает запись на смены, блокировка (только владелец, причина обязательна) закрывает бот и приложение целиком: на любое сообщение и любую кнопку, в том числе старую, бот отвечает «⛔ Доступ к боту заблокирован. Обратитесь к администратору», рабочие сообщения, рассылки и напоминания заблокированному не уходят. Смены не удаляются физически — получают статус `removed`/`withdrawn`.

При блокировке бот сам исключает человека из «Предзакрепа», «Основной команды» и группы фотоотчётов «Алисы» — там, где Telegram показывает его участником (архивный чат не трогается); если не получилось (нет права банить, Telegram не ответил — бот повторяет), администраторы получают сообщение, а в «Группах» человек виден с пометкой «Заблокирован, но состоит …». При разблокировке в группы автоматически не возвращает.

Вкладки приложения: «Работа», «График», «События», «Профиль» и вкладка руководителя — «Админ» у владельца и администраторов, «Тренер» у тренера, «Инструктор» у инструктора (ТЗ 28.10 §8). Тренер сети — тот, кто назначен руководителем сети в «Сетях» (`networks.trainer_id`); роль «Тренер» в «Команде» делает человека руководителем его сети, второй тренер в одной сети невозможен.

### Отчёты о смене

Отчёт — факт (шт.) и обязательный скриншот — можно сдать **в любой момент дня смены**, с 00:00, до начала смены или после. На экране «График» в этот день появляется кнопка «Сдать отчёт за сегодня». После конца смены бот ещё и сам просит отчёт: в боте — число, потом фото. Скриншоты хранятся в Telegram (`file_id`), в приложении показываются по подписанным ссылкам.

После сдачи отчёта сотрудник уже не может сам изменить или отменить эту смену: план остаётся тем, с которым сравнивали факт. Поменять может администратор.

- Каждый отчёт уходит на проверку, даже если факт не меньше плана: «Принять», «На исправление» (с комментарием, новая попытка без срока) или «Отклонить + штраф» (число штрафных единиц и причина). Сразу принимаются только отчёты за день, когда команда уже выполнила общий план (см. «Общий факт дня»).
- Срок сдачи — `max(00:00 после дня смены, конец смены + 2 ч)`. Перед сроком бот напоминает сотруднику, вечером админам приходит список, кто не сдал. После срока смена становится **неявкой**: штраф, «без штрафа» или «внести результат» за сотрудника.
- Время напоминаний и получатели сводки — в «Настройках». Смены до установки этой версии в неявки не попадают.

### Общий факт дня

Владелец вводит, сколько всего сделала команда за день — в приложении («Админ → Факт дня») или командой `/fakt 480` (`/fakt 480 17.10` за другой день). Общий план дня — сумма планов состоявшихся смен.

- Команда выполнила план → все отчёты дня с недобором, ждущие проверки, принимаются автоматически (сотрудник получает пуш, в архив — «🟢 АВТОМАТИЧЕСКОЕ ОДОБРЕНИЕ»). Если за недобор уже выдан штраф, его можно аннулировать: по одному или все сразу. Отчёты, сданные позже, в такой день тоже принимаются сразу.
- Команда не выполнила план → отчёты с недобором остаются на ручной проверке.
- Штраф за недобор нельзя назначить, пока общий факт не введён, и нельзя, если команда выполнила план. Штрафы за неявку и за недостоверный отчёт — всегда.
- Значение можно исправлять, каждое изменение остаётся в истории дня. Бейдж «Факт дня» показывает дни без общего факта, бот напоминает владельцам вечером (за сегодня) и утром (за вчера); время — в «Настройках».

### Финансы: штрафы, бонусы, вычеты

Все деньги — в журнале `financial_transactions` (раздел «Админ → Финансы», у сотрудника — «Профиль → Штрафы и бонусы», в боте — `/finances`). Баланс = активные бонусы − активные штрафы − вычеты.

- **Штрафные единицы.** Штраф назначается в единицах (быстрые 1 / 3 / 5 или своё число): одна единица — ставка сотрудника за штуку (личная, если задана, иначе общая), ставка фиксируется в момент назначения. Сотрудник видит только единицы («3 штрафные единицы») — в профиле, в карточках смен, в боте; персонал видит и рубли: «360 ₽ (3 ед. × 120 ₽)». Бонусы, вычеты и денежные призы — в рублях. Старые штрафы, назначенные до единиц, остаются в рублях.

- **Штраф** назначают владелец и администратор сразу; штраф от **тренера** уходит на согласование владельцам и администраторам (в бот приходят кнопки «Одобрить / Отклонить», в приложении — «Финансы → Решения»), баланс до решения не меняется, о заявке сотрудник не узнаёт.
- **Простить** штраф могут администратор и владелец (любой) и тренер (людям своей сети), причина — по желанию. Сотрудник получает «🤝 Штраф прощён» (с причиной, если она указана), автор штрафа — уведомление, копия — в архив с `#прощён`. Так же тренер может отозвать свою заявку, которая ещё ждёт согласования.
- **Окончательная отмена** смены создаёт черновик штрафа «ждёт суммы» (вкладка «Решения»). Штрафы за отчёты и неявки тоже записываются сюда.
- **Бонус** — любой руководитель своим людям, сразу; **вычет** — только владелец.
- **Аннулировать** бонус или вычет — с обязательной причиной. **Погасить все штрафы** человека — только владелец, частично нельзя.
- Быстрые действия «Штраф, бонус, вычет» — в карточке сотрудника в «Команде»; к записи можно приложить фото или скриншот, он виден в истории и уходит в архив вместе с записью. Всё денежное уходит в архив с хештегами `#штраф #бонус #вычет #аннулирование #погашение`.
- **Ставки** («Настройки → Ставки») меняет только владелец; администратор их не видит и не меняет.
- Excel-выгрузка и статистика считают деньги по журналу: лист «Штрафы и бонусы», колонки бонусов и вычетов в итогах.

### Ставки, лестница тренера, заработок владельца

Всё про деньги настраивает только владелец.

- **Ставка сотрудника.** Личная ставка («Команда» → человек), иначе — общая («Настройки → Ставки»). Ставок сетей больше нет.
- **Копилка «налога на лень».** Каждый принятый день, где сделано меньше порога (по умолчанию 20 шт.), добавляет свои штуки в копилку L человека. Копилка не сгорает между неделями и месяцами. При выплате из P принятых штук периода min(P, L) оплачиваются по ставке налога на лень, остальные — по ставке человека; ставки берутся те, что стоят на момент выплаты. Копилка уменьшается только при «Зафиксировать»: предварительный расчёт, отмена или повтор той же кнопки ничего не списывают. У кого стоит «Не применять налог на лень», копилки нет. Выплаты, сделанные до появления копилки, уже оплатили свои ленивые дни по пониженной ставке — эти дни в копилку не попадают.
- **Сотрудник** видит в «Профиль → Штрафы и бонусы» штрафные единицы, штуки к оплате (принятые после последней выплаты), копилку налога на лень в штуках и пометку, что реальная выплата может быть меньше. Плановый заработок в карточках смен по-прежнему считается по дневной ставке.
- **Лестница тренера** («Сети» → «Ставки сети»): ступени «от N шт. → R ₽ за штуку». Достигнутая командой ступень оплачивает **все** штуки команды. Объём считается за день или за неделю — выбирается для каждой сети. Штуки самого тренера учитываются только при включённом тумблере. Без ступеней — общая комиссия «Тренеру с объёма сети». При недельной лестнице ступень определяется по всей неделе пн–вс, а в выплату попадают только дни её периода.
- **Инструкторы и общая дельта (ТЗ 27.10 §22–25).** В «Сетях» каждому сотруднику выбирается «Тренеру напрямую» или инструктор этой же сети. Лестница инструкторов задаётся там же, как у тренера: по принятым штукам закреплённых людей, за день или за неделю, ступень оплачивает все штуки. Без ступеней — «Инструктору с его людей» из «Настроек». У тренера и инструктора может быть своя ставка с объёма («Команда» → человек), она главнее лестницы. Вместе они получают не больше дельты: «Предел за штуку» (150 ₽) − общая ставка (120 ₽) = 30 ₽, независимо от личной ставки сотрудника и налога на лень. Тренер берёт первым, инструктор получает остаток: тренер 30 ₽ — инструктору 0 ₽, тренер 10 ₽ — инструктору до 20 ₽. Тренер получает и за людей инструкторов. В мастере выплаты по кнопке «Расчёт по дням» видно: штуки, объём для ступени, ставка ступени и фактически выплачиваемая ставка. Если инструктор теряет роль или переходит в другую сеть, его люди возвращаются к тренеру. Вычет в штуках снимает долю сотрудника и тренера, долю инструктора не трогает.
- **Владелец во главе сети.** Руководителем сети можно назначить владельца, в том числе нескольких сетей сразу; в таких сетях тренерские не начисляются. Тренер по-прежнему ведёт одну сеть.
- **Вычет в штуках за день** (карточка сотрудника → «Вычет» → «В штуках за день»): сотруднику — штуки × его ставка за тот день, тренеру сети — штуки × ставка лестницы, по которой этот день был оплачен; ступень не пересчитывается. Оба видят минус в рублях с пояснением «5 шт. × 120 ₽». Аннулирование вычета сотрудника снимает и часть тренера. Вычет в рублях остаётся для прочих случаев и тренера не касается.
- **Мастер выплаты.** В расчёте видно, сколько за штуки и сколько тренерских (с объёмом и ставкой ступени). Прямо в строке человека можно начислить бонус, штраф или вычет — расчёт сразу пересчитывается. Владелец, который сам выходит на смены, получает за свои штуки по своей ставке (личную ставку владелец может поставить и себе); тренерских за сети владельца нет.
- **Заработок владельца** = все принятые штуки × «Доход бизнеса за штуку» (настройка владельца) − всё, что выплачивается людям. Показывается в мастере выплаты, в зафиксированной выплате и в сводке в архивной группе.

### Сети и тренеры

Сеть — команда со своим тренером («Админ → Сети», управляет только владелец; администраторы видят дерево).

- Владелец создаёт сеть, назначает тренера (человек сам получает роль «Тренер» и попадает в сеть; прежний тренер остаётся в сети сотрудником) и добавляет людей. Пустую сеть можно отправить в архив.
- Тренер видит и делает всё только в своей сети: команда, смены, отчёты, паузы, штрафы на согласование, бонусы. Уведомления о сменах, срочных заявках и отчётах его людей приходят ему в бот.
- Номера сетей, выданные людям до этой версии, превращаются в сети «Сеть N» при обновлении.

### Реквизиты СБП и реестр выплат

- **Реквизиты** («Профиль → Реквизиты для выплат»): телефон для СБП, банк из списка, ФИО получателя. Видят только сам сотрудник и владелец (остальным номер замаскирован), каждое изменение пишется в журнал.
- **Ставки** — в «Настройках»: ставка за штуку, «налог на лень» (ставка и порог в штуках за день), комиссия тренеру за штуку его сети, инструктору — за штуку его людей, предел за штуку (150 ₽).
- **Мастер выплаты** («Админ → Выплаты», только владелец): 1) период, сеть, ставки на эту выплату; 2) расчёт — база по **принятым** отчётам: штуки по полной ставке и по ставке налога на лень, копилка до и после выплаты, штрафы в единицах и рублях; тренеру — комиссия с объёма сети, бонусы, штрафы и вычеты, галочка «в реестр» и ручная правка базы; 3) фото-основания выплаты и вычетов, «Зафиксировать».
- Зачитывается то, что помещается в сумму: сначала вычеты, потом штрафы (старые первыми); что не поместилось, остаётся долгом, выплата не бывает отрицательной. Учтённые записи получают статус «учтён в выплате».
- После фиксации владельцу в бот приходят Excel-реестр и список для банка с группировкой по банкам, в архив — ведомость `#выплата` с документами, сотрудникам — сумма выплаты.

### Профиль сотрудника и реквизиты (ТЗ 28.10 §7)

- «Профиль → Мои данные»: по шагам — фамилия, имя, отчество; возраст и метро; минимум рабочих дней и удобные дни (ровно столько, сколько минимум — иначе отправить нельзя, и приложение пишет почему); итоговая карточка с правкой каждого пункта. Пустые поля подставляются из анкеты кандидата. После отправки — «Ожидает рассмотрения администратора», новые изменения до решения отправить нельзя.
- «Команда → Изменения профилей»: что было и что предлагается; «Одобрить» (данные и имя меняются везде) или «Отклонить» с обязательной причиной — сотрудник получает её, исправляет и отправляет снова. В карточке человека — «Данные сотрудника», «Изменить сразу» без согласования и журнал: кто, когда, что было → что стало, каким способом. «Мин. дней» — справка для администратора, норму выходов по-прежнему задаёт руководитель.
- Реквизиты: изменение сотрудника (и первое заполнение) уходит на одобрение владельцу, до одобрения выплаты идут по прежним; при «Другой банк» нужно название. Владелец меняет реквизиты сразу. Выплата человеку без одобренных реквизитов не фиксируется — мастер называет, кого убрать или чьи реквизиты одобрить.
- В «Команде» у людей с неполными, ожидающими или отклонёнными данными — метки «Профиль: …», «Реквизиты: …». «📢 Напомнить о заполнении» (владелец, администраторы, тренер — своим) показывает, скольким и кому уйдёт, и шлёт текст из «Настройки → Тексты сообщений» только тем, у кого профиль или реквизиты не заполнены или отклонены.

### Изменение и аннулирование выплат (ТЗ 28.10 §25)

- «Изменить» в карточке выплаты: обычная — кто входит и база; по «Алисе» — числа Яндекса по QR. Это та же выплата (номер не меняется, дубликата нет), прежняя версия сохраняется; удержания пересчитываются заново — каждое по одному разу.
- «Аннулировать» — с причиной и вопросом «Деньги уже переведены?»: выплата получает «Аннулирована» и уходит во вкладку «Архив» реестра со всей историей (кто, когда, почему). Её штрафы и вычеты снова становятся долгом, копилка налога на лень возвращается, задания «Алисы» снова ждут оплаты. Если деньги уже переведены — каждому начисляется вычет «Переплата по аннулированной выплате №…», он удержится из следующей. Ничего не удаляется. Сотрудники получают сообщение, в архивный чат уходит запись.
- Менять и аннулировать можно только последнюю выплату этих людей (по «Алисе» — этих QR): более поздняя считалась поверх неё.
- Обычные выплаты с пересекающимися периодами для одних и тех же людей запрещены — мастер называет, с какой выплатой пересечение. Повторное нажатие «Зафиксировать» возвращает ту же выплату и ничего не рассылает второй раз.

### Рассылки с подтверждением прочтения

«Админ → Рассылка»: текст с форматированием и при желании фото.

**Кому:** список сотрудников с галочками — сообщение получат ровно отмеченные, внизу «Выбрано: N».
- Кнопки «Все», «Работают», «Не работают», «Админы» и сети только ставят или снимают галочки у своих людей.
- Есть поиск по имени и «Выбрать всех / Снять выбор».
- Переключатель «Только тем, кто не отметил график на завтра» оставляет из отмеченных тех, у кого на завтра нет ни смены, ни выходного.
- Тренер видит и выбирает только людей своей сети.

**Вложение:** фото или видео (MP4/MOV до 50 МБ — ограничение Telegram для ботов).

**Шаблоны:** над текстом — сохранённые тексты, нажатие подставляет шаблон в редактор. «Сохранить текст» создаёт новый шаблон, «Записать текст редактора в шаблон» обновляет выбранный, «Изменить» показывает удаление. Пользоваться можно всеми шаблонами, менять — свои (владельцы и админы — любые).

**Подпись** определяет сервер по роли автора (ТЗ 28.10 §13): владелец и администратор выбирают «📣 Сообщение от администратора» или без подписи; у тренера всегда «📣 Сообщение от тренера» с его именем-ссылкой, у инструктора — «Сообщение от инструктора». Инструктор пишет только закреплённым за ним людям.

**Возможность ответить:** под сообщением появляется кнопка «✍️ Ответить». Человек пишет текст, прикладывает фото и видео (до 10) и жмёт «📨 Отправить» — автору рассылки в бот приходит одно сообщение: от кого (имя со ссылкой на Telegram, @username, ID, сеть), на какую рассылку и всё приложенное. В истории — «ответили N из M», тексты ответов и кто не ответил. Ответ считается и прочтением.

**Отправленные:** «Открыть целиком» показывает сообщение так, как его получили: весь текст с форматированием, фото или видео. Видео сервер хранит у себя в `MEDIA_DIR`, потому что Telegram отдаёт боту файлы только до 20 МБ. У рассылок, отправленных до этой версии, видео до 20 МБ подгружается из Telegram, а более крупные остаются только в чате с ботом.

С включённым «Требовать подтверждения прочтения» в сообщении есть кнопка **«✅ Я ознакомился»**: нажатие записывается, кнопка исчезает, внизу появляется «Прочитано». В истории видно «прочитали N из M», список непрочитавших и кнопки «Напомнить» (одному) и «Напомнить всем».

### Цели

Прогресс цели всегда пересчитывается по принятым отчётам за весь её период, поэтому цель, созданная в середине недели, сразу учитывает уже принятые отчёты с первого дня (ТЗ №18), а один отчёт не может посчитаться дважды. В карточке цели видно, сколько учтено автоматически за дни до создания и сколько ещё на проверке; при создании цели в архив уходит запись с уже учтённым объёмом.

«Админ → Цели»: личная (одному человеку, участвует сразу), командная (для всех, ставят владелец и администраторы), сетевая, **группа** (люди отмечаются галочками, участвуют сразу; тренер — только своих) и **точка**.

**Цель точки** — норма на день для всех, у кого в этот день смена на точке: их факты складываются, считаются и принятые отчёты, и отчёты на проверке, с правками администратора. Каждый день прогресс обнуляется во время «День начинается в» (например, 06:00 — до этого времени ещё считается вчерашний день). Действует каждый день, пока её не изменят или не удалят, или до выбранной даты. Когда точка выполнила норму за день, всем, кто там работал, приходит уведомление — один раз за день. Ставят владельцы и администраторы, нужен список точек в «Точках». Для командной и сетевой — «общая норма» (объёмы участников складываются) или «норма каждому». Тренер ставит личные цели своим и цели своей сети.

Люди получают уведомление с кнопкой «🙋 Участвую», прогресс — карточка «Цели» на экране графика. Прогресс считается по **принятым** отчётам за период цели (в том числе принятым автоматически и по общему плану) — каждый отчёт идёт во все подходящие цели. Выполненные отмечаются ✅, участникам и автору приходит уведомление.

### Живые события

«Админ → События»: соревнование с таймером, призом и живым рейтингом. Два типа:

- **Гонка до цели** — участник отправляет число (не меньше цели) и скриншот; руководитель подтверждает победителей по порядку (👑), набран лимит победителей — событие завершено, всем приходят итоги.
- **Кто больше** — каждая подтверждённая заявка прибавляется к счёту. Рейтинг показывает подтверждённое + на проверке (светлая часть полоски), призы — по подтверждённому, при равенстве выше тот, кто набрал раньше. После таймера 15 минут на проверку последних заявок, затем итоги.

Условия пишутся с правильными окончаниями: «Гонка до 30 шт., 1 победитель», «Кто больше сделает, 3 победителя». На экране события они разложены на плашки (тип и цель, победители, попытки) с фразой «как победить», крупным таймером и карточкой приза. Правила события можно оформить: жирный, курсив, ссылка и т. п. Приз может быть фото или видео (MP4/MOV до 50 МБ): видео открывается на весь экран, а в боте приходит вместе с объявлением.

Одна заявка на проверке за раз; отклонение — только с причиной, участник видит её и номер попытки; после исчерпания попыток участие закрыто. Тренер проводит события для своей сети и проверяет заявки своих. У сотрудников вкладка «События» появляется, пока есть активное или недавно завершённое событие; рейтинг обновляется каждые 5 секунд с анимацией смены мест. Заявки приходят проверяющим в бот со скриншотом и кнопками.

### Правка, скрытие и архив целей и событий (ТЗ №20, №22)

**Кто:** владельцы и администраторы — любые цели и события; тренер — только созданные им самим и только в своей сети.

**Правка на ходу (✏️).** Та же форма, что при создании, уже заполненная: название, правила, даты, норма или цель, число победителей и попыток, приз. Если два человека правят одновременно, второй получит «Данные устарели — откройте заново».
- **Уведомления.** Даты, норма, победители и попытки, приз и его тип — важные поля. Перед сохранением спрашиваем «Уведомить участников?». Участники получают «⚠️ Важное обновление» со списком: что было → что стало. Название, описание и фото меняются молча.
- **Норму снизили** — кто уже дотянул, сразу получает «Цель выполнена».
- **Норму подняли** — «выполнено» само не снимается. В карточке появляется «Снять выполнение» для тех, кто теперь ниже нормы; им приходит сообщение, сколько осталось.
- **Аннулировать результат** (⊘ у участника цели) — с причиной, например «Нечестная работа». Объём человека перестаёт учитываться в цели, ему приходит сообщение с причиной, копия уходит в архивную группу.
- **События:**
  - старт меняется только до начала;
  - у гонки с победителями цель не меняется. Сначала «Отменить результат» в «Подтверждённых результатах»: результат перестаёт учитываться, попытка не сгорает, а если таймер ещё идёт, гонка продолжается;
  - финиш раньше текущего времени завершает событие и рассылает итоги;
  - финиш позже текущего у завершённого события — «Перезапустить»: оно снова принимает заявки, результаты сохраняются.
- **Приз:** тип из списка (деньги, подарок, сертификат, выходной, мерч) или свой, описание и фото. Фото хранится в Telegram и показывается справа в карточке, по нажатию — на весь экран. Без фото — серый квадрат с 🎁.

**Лента и архив.**
- **Глаз:** 👁 — видно сотрудникам, перечёркнутый — скрыто. Перед скрытием приложение спрашивает подтверждение, вернуть можно всегда.
- **Скрытое:** заявки не принимаются («Это событие завершено или скрыто администрацией»), к цели нельзя присоединиться, итоги сохраняются.
- **Автоматически:** завершённые цели и события уходят в архив через N дней после окончания. N задаётся в «Настройки → Архив целей и событий», по умолчанию 7. Нажатое «Показать» закрепляет в ленте.
- **Где архив у сотрудника:** «Профиль → Архив целей и событий» и ссылка внизу экрана «События». Там победители, мой результат и полный рейтинг.
- **🗑 Удалить:** пропадает у всех, в том числе из архива. Запись в базе остаётся.

### Нарушения графика: штраф или оправдание

Общая норма выходов в неделю задаётся в «Настройках» (по умолчанию 3 дня, её можно выключить). Личная норма задаётся в карточке сотрудника («Команда» → человек): владелец и администратор — любому, тренер — людям своей сети; «Без нормы» исключает человека из проверки. Личная норма действует и при выключенной общей. Каждый понедельник (10:30) прошлая неделя пн–вс сверяется с нормой: выход — день со сменой «выходит» или «восстановлена», которая не закончилась неявкой. Кто вышел меньше нормы, получает заявку `attendance_violations` (одна на человека и неделю). Не проверяются владельцы и админы, люди на паузе или в блоке и те, кого приняли в течение этой недели. Руководители получают сводку в бот. Владелец или админ может проверить прошлую неделю и вручную: кнопка «Проверить неделю» (повторная проверка новых заявок не создаёт).

«Админ → Дисциплина»: карточка с сетью, неделей, требованием, фактом, пропущенными днями и две кнопки.

- **Назначить штраф** — число штрафных единиц, причина (подставлен текст «Невыполнение плана выходов за период… Вышли Y из X дней.», можно дописать) и до 5 файлов-доказательств. Создаётся штраф в журнале финансов (`source = attendance`), заявка становится `penalized` со ссылкой на штраф.
- **Простить** — основание по желанию (быстрые варианты: больничный, согласовано, простой) и до 5 документов. Заявка — `waived`, деньги не трогаются.

Решение принимается один раз: кнопка блокируется после нажатия, повтор с тем же ключом ничего не меняет, второе решение — ошибка «Заявка уже обработана». Сотрудник получает подробное сообщение (штраф или снятие, статистика, комментарий, файлы следом), копия уходит в архивную группу с тегами `#нарушение #штраф` / `#нарушение #оправдание`. Тренер видит и решает только по своей сети; его штраф, как и любой штраф тренера, ждёт согласования владельца или администратора — сотрудник узнаёт о нём после одобрения, а при отказе нарушение снова ждёт решения.

**Отметка графика на завтра.** Кто со статусом «Работаю» к вечеру не отметил завтрашний день (ни смены, ни выходного), получает напоминание (по умолчанию в 20:00). Кто не отметил и к сроку (по умолчанию 22:00), получает нарушение «Не отметил график» за этот день — в той же «Дисциплине», с кнопками «Назначить штраф» (подставлено 3 штрафные единицы × ставка сотрудника, число единиц — в настройках) и «Простить». «Не работаю» не проверяется. Время и выключатель — в «Настройках».

### Рекрутинг: реферальная ссылка, анкета, стажировка

Путь кандидата: ссылка → анкета → обучение → стажировка → проверка → бонус пригласившему.

- **Доступ только по ссылке (ТЗ 27.10 §5–9).** Незнакомому человеку без действующей ссылки бот не отвечает, не показывает меню и не создаёт заявку; приложение показывает «Нет доступа». Каждая такая попытка записывается в «Админ → Доступ → Попытки доступа» (ID, username, имя, вид попытки, первая и последняя, сколько раз). Кнопка «Приложение» в меню бота есть только в чатах тех, у кого есть доступ. Владельцы из `ADMIN_IDS` проходят всегда.
- **Реферальная ссылка.** У каждого сотрудника в «Профиль → Мои рефералы» есть ссылка `t.me/<бот>?start=ref_<токен>` и кнопка «Сгенерировать QR-код». Ссылка меняется каждый час (настраивается: «Настройки → Реферальные ссылки меняются»), рядом — таймер «сменится через …»; старая ссылка и её QR-код после этого не работают. Кто успел открыть ссылку, тот закреплён за пригласившим и может заполнить анкету позже. Ссылка открывает чат с ботом: кандидат нажимает «Старт» и получает кнопку «📝 Заполнить анкету», так бот сможет писать ему об обучении и сменах. Если бот всё равно не может написать, админы видят это в сообщении о новой анкете. Там же список приглашённых: на каком этапе каждый, сколько единиц сделано и какие бонусы начислены.
- **Неактуальная ссылка.** Просроченная, отозванная или исчерпанная ссылка при первом обращении получает ответ «Эта ссылка больше неактуальна. Пожалуйста, обратитесь к человеку, который вас пригласил…», повторно — тишина. Старые ссылки вида `ref_<код>` до этого изменения тоже считаются неактуальными.
- **Приглашения владельца** («Админ → Доступ → Приглашения», только владелец): срок (1 час, 1 день, 7 дней), сколько человек (1, 5, 20 или без лимита), подпись, QR-код, отзыв, кто пришёл. Приглашённый в чате с ботом указывает фамилию и имя, админы одобряют заявку обычными кнопками — без обучения и стажировки, сеть и тренер не назначаются. Последнее место по лимиту не займут двое одновременно.
- **«Обновить все ссылки»** (там же): все действующие реферальные ссылки, их QR-коды и приглашения перестают работать сразу; сотрудники увидят новые ссылки у себя, приглашения выпускаются заново с тем же сроком и остатком мест. Аккаунты, реферальные связи и бонусы не меняются.
- **Анкета** в Mini App, 4 шага: ФИО, возраст, метро; сколько дней в неделю готов выходить; удобные дни для обучения (с подтверждением); оценка навыков 1–10. Перед отправкой — черновик с правкой, галочки «данные достоверны» и согласие на обработку персональных данных (типовой текст открывается по ссылке). Пока анкета на рассмотрении, кандидат видит её статус.
- **«Админ → Онбординг»** (владелец и администраторы): вкладки «Ожидают рассмотрения», «На обучении», «Стажировка», «Завершённые» (там же идёт второй этап), «Отклонённые»; фильтры по возрасту, навыкам, дням и сортировка. На карточке: профиль TG, «Назначить обучение» (дата, время, точка, тренер), «Связаться» (вопрос кандидату через бота, его ответ виден на карточке), «Отказать» с причиной.
- **Обучение.** «Отменить обучение» возвращает кандидата в «Ожидают рассмотрения» (это не отказ: кандидат и тренер получают сообщение). «Отказать в обучении» — причина по желанию, анкета уходит в «Отклонённые». Кандидат подтверждает обучение кнопкой в боте; напоминания приходят накануне (20:00) и утром (08:00), время — в «Настройках». После обучения — «Начать стажировку».
- **Стажировка.** Стажёр сам записывается на смены и сдаёт отчёты, как сотрудник. В графике и распреде он подписан «стажёр». Его смены учебные: не оплачиваются и не идут в заработок тренера. Нужное число единиц (по умолчанию 20) считается по принятым отчётам и видно стажёру на главном экране.
- **Проверка и бонусы.** Когда норма набрана, руководители получают сообщение, а в «Онбординге» появляется «Проверить стажировку»: зачесть единицы и начислить бонус пригласившему (0 / 500 / 1000 ₽ или своя сумма). Второй этап — ещё 50 рабочих единиц после стажировки, учебные не считаются. Обе нормы задаются в «Настройках → Стажировка и второй этап». Если администратор засчитал не столько, сколько набралось, человек получает сообщение «скорректировал результат: 20 → 18 шт.».
- **Отказ.** Отклонённые анкеты остаются в истории («Отклонено»), даже если кандидата потом вернули в резерв.

Текст согласия типовой. Перед запуском впишите в него реквизиты оператора персональных данных (сейчас там «организатор проекта «Иди работай!»»).

### Обучение кандидата (ТЗ 28.10 §2–§6)

- **Тренер.** В «Онбординге» — «Назначить тренера»: любой действующий сотрудник, пригласивший — первым со звёздочкой. Пригласивший и тренер — разные люди. Сначала показывается текст для кандидата («🎉 Хорошие новости!… Свяжитесь с <ФИО тренера>… 48 часов»), уходит он только по «Отправить кандидату». На карточке — сколько часов прошло (красным после 48 ч), «Написать о тренере ещё раз» (новый отсчёт, история сохраняется), «Сбросить таймер», «Напомнить пригласившему». Автоматического отказа нет. Кандидат отвечает кнопками «Я связался с тренером» / «Не могу написать первым».
- **Дата.** «Назначить дату / Изменить обучение»: кандидат и тренер подтверждают кнопкой в боте (тренер — и в приложении). Когда оба подтвердили — «Обучение согласовано», и кандидату приходит личное приглашение в «Предзакреп» кнопкой (если он ещё не там). Перенос — не отмена.
- **Раздел «Обучение»** (вкладка в приложении) — у того, кому назначен кандидат, автоматически; администратор может открыть или закрыть вручную в «Команде» (закрыть нельзя, пока за человеком есть кандидаты). Там — кандидаты со статусом, анкета, профиль и запросы: «Начать обучение», «Изменить обучение» (дата, время, место, другой тренер), «Отменить обучение», «Отказать в обучении», «Начать стажировку», «Стажировка завершена». Отмена, отказ и изменение — с причиной. До решения администратора всё остаётся как было; повторное нажатие не создаёт второй запрос; изменение, сделанное за это время администратором, делает запрос устаревшим.
- **«Ожидает согласования»** — сверху в «Онбординге» и карточками с кнопками в боте у владельцев и администраторов; после решения карточки у всех меняются на «Одобрено/Отклонено — кто». Отклонение — с обязательной причиной. Кандидат может попросить перенос кнопкой «🔁 Прошу перенести» — администратор назначает новую дату.
- **Отмены обучения: N/3** — на карточке и в «Обучении», с датами, кто и почему. Перенос не считается, неявка кандидата считается. Порог — «Настройки → Стажировка» (по умолчанию 3). На пороге — предупреждение с «Продолжить обучение» / «Отказать»; автоматического отказа нет. Отмены до 28.10 перенесены из журнала.
- **Отказ** — с обязательной причиной: «Отказано», аккаунт блокируется, бот убирает из «Предзакрепа». «Вернуть в резерв» снимает блокировку — если отказали по ошибке.
- **«Принять в команду»** (бывшее «Проверить стажировку») — после проверки администратором: поздравление и кнопка в «Основную команду». Тренер сам кандидата не принимает.

### Методички (ТЗ 28.10 §12)

- «Админ → Методички» (владелец и администраторы): создать, «Загрузить HTML-файл» — готовую страницу целиком (разделы — по заголовкам `<h2>`, без них — по `<h1>`; текст до первого — «Введение»), «Заменить из HTML-файла», переименовать, удалить с подтверждением. Кодировка файла определяется сама (UTF-8, UTF-16, Windows-1251, `<meta charset>`), на пустой файл, PDF, Word и страницу без видимого текста — понятная причина. Каждое сохранение — новая версия, старые остаются.
- **Оформление сохраняется (ТЗ 29.10 §3):** блоки, классы, выравнивание, цвета, размеры, таблицы, встроенные картинки и таблица стилей `<style>` страницы. У сотрудника методичка показывается своей страницей в изолированной рамке («песочница» без скриптов + запрет любых внешних загрузок), ссылки открываются снаружи.
- **Визуальный редактор (ТЗ 29.10 §4):** «Визуально» — страница в том же виде, что у сотрудника, правится прямо на ней (абзац/заголовки, жирный, курсив, подчёркнутый, списки, выравнивание, ссылка, размер, цвет, «очистить», отменить/повторить); «Код» — HTML и стили целиком; «Предпросмотр». Сохраняется та же методичка (её номер, выдача людям и прочитанность неизменённых разделов остаются). При несохранённых правках — предупреждение при выходе, загрузке файла и закрытии приложения.
- HTML чистится на сервере по белому списку: без скриптов, фреймов, форм, обработчиков событий, `javascript:`-ссылок и всего, что грузится из интернета (картинки, шрифты, `@import`, `url()` — они выдали бы, кто читает); встроенные картинки хранятся на сервере и открываются только по коротким подписанным ссылкам. Содержимое никуда наружу не отправляется.
- Выдача — «Команда» → человек → «Методички» (по одной или «Закрыть все»). У сотрудника вкладка «Обучение» с «Методичками» появляется, пока выдана хотя бы одна. Сервер проверяет доступ при каждом открытии — после отзыва старая ссылка не работает. Чтение: оглавление с отметками, «Назад» / «Далее», «Раздел N из M», прогресс по каждому человеку; изменённый раздел снова считается непрочитанным, удалённый не считается.

### Кнопка в другой бот (ТЗ 28.10 §10)

«Настройки → Кнопка в другой бот»: название и ссылка `https://t.me/…` (бот или Mini App — откроется внутри Telegram). Создать, «Скрыть» / «Показать» (настройки сохраняются), «Удалить» (кнопка исчезает полностью). Видна всем в шапке рядом с ролью, длинное название обрезается многоточием.

### Надпись над ролью (ТЗ 29.10 §7)

Надпись «выход» в шапке над ролью — это название дизайна, а не выход из аккаунта. «Настройки → Надпись над ролью»: любой текст до 32 символов (название работы, организации, проекта) в том же стиле, «Скрыть» (место не остаётся), «Вернуть «выход»», предпросмотр. Меняется у всех — в шапке, боковой панели и на экранах загрузки.

### Группы «Предзакреп» и «Основная команда» (ТЗ 27.10 §26–27, ТЗ 28.10 §15)

- Кто где должен быть: кандидат — в «Предзакрепе», когда обучение согласовано; в «Основной команде» — после «Принять в команду». Пришедшие без анкеты (приглашение владельца, старая команда) — сразу в «Основной». В «Группах» каждому можно задать: «Авто», только «Предзакреп», только «Основная» или «Обе» — и отметку «Не новичок — подтвердить» (опытный: нужна основная; роли не меняются, отметка снимается).
- Строка человека: членство в каждой группе (по ответу Telegram), что нужно, «Все нужные группы на месте» или что не так с кнопками: «Не хватает: …» → пригласить, «Состоит в обеих группах» → убрать из предзакрепа или «Можно в обеих», «Новичок в основной команде» → «Не новичок — подтвердить» или убрать, «Заблокирован, но состоит …» → убрать. Вступил в основную — бот сам убирает из «Предзакрепа», если человеку не разрешены обе.

### Группы: как подключить

- Рабочий день — календарная дата, за которую у человека принят отчёт: решением администратора, автоприёмом «команда выполнила план» или по учебной смене. Несколько отчётов за дату — один день. 0–2 дня — «Предзакреп», с 3-го — «Основная команда» (порог — в «Настройках»).
- Подключение: добавьте бота в обе группы администратором с правами «приглашать пользователей» и «банить пользователей», владелец пишет в группе `/group_pre` или `/group_main` (`/group_off` — отключить).
- Приглашения личные: бот создаёт ссылку, по которой Telegram присылает заявку на вступление, и одобряет её только от того человека, кому ссылка отправлена. Пересланная ссылка никого другого не впустит. Ссылка действует 7 дней, новая отменяет старую.
- Автоматически (выключатель в «Настройках»): новичку — приглашение в «Предзакреп», на 3-м подтверждённом дне — в «Основную команду», каждому по одному разу на группу; бот сначала спрашивает Telegram, не состоит ли человек уже. Вступил в основную — бот убирает его из «Предзакрепа», если есть право; иначе пишет админам.
- «Админ → Группы»: у каждого — число подтверждённых дней, первый день, ожидаемая группа, членство в каждой группе по ответу Telegram (состоит / не состоит / не проверено), отправленные приглашения и рекомендуемое действие. Отдельно подсвечиваются: не состоит ни в одной группе, новичок в основной, опытный остался в «Предзакрепе», состоит в обеих. Сверка — раз в день (время в «Настройках») и по кнопке «Сверить сейчас».

### Профили Telegram (ТЗ 27.10 §11, ТЗ 28.10 §17)

- Везде используется Telegram ID (не внутренний номер в базе). Один механизм на бэкенде (`notify.person_link`) и один в приложении (`openProfile`): карточка сотрудника, смены, «Сети», «Онбординг», «Группы», «Доступ», «Алиса», «Отчёты», «Финансы», рассылки, «Мои рефералы».
- С username — ссылка `t.me/<username>`, она открывается во всех клиентах.
- Без username Telegram открывает профиль только если это разрешают настройки приватности человека, а ссылка `tg://user?id=…` внутри Mini App на iPhone и Android не работает. Поэтому приложение показывает окно: ID с кнопкой «Копировать ID» и «Прислать карточку в чат с ботом». Если Telegram разрешает, в карточке есть кнопка «Открыть профиль»; если нет — бот честно пишет, что профиль скрыт настройками приватности. Кнопки «Написать» у таких людей не показываются.
- В сообщениях бота у человека без username рядом с именем-ссылкой всегда показан его ID.

### «Работа» и «Яндекс Алиса» (ТЗ 27.10 §28–44)

- **Доступ к продуктам** — в карточке сотрудника («Команда» → «Работа: продукты», владелец и администраторы), с журналом изменений. Вкладка «Работа» видна только тем, у кого есть доступ; сервер проверяет его при каждом действии, прямая ссылка не помогает. Закрытие доступа блокирует новые действия, история выполнений, модерации и выплат остаётся. Продукты добавляются в один реестр без отдельной авторизации.
- **QR-коды** («Админ → Алиса → QR-коды»): картинка, номер по желанию, назначение. Один QR можно назначить нескольким сотрудникам, у сотрудника — один QR. В выполнении сохраняется QR, с которым его начали; смена назначения, замена картинки или архив историю не меняют. У каждого QR — история назначений и выполнений.
- **Выполнение** (вкладка «Работа»): «Начать выполнение» → без назначенного QR — «На вас не назначен QR-код. Обратитесь к администратору» → QR на экране → «QR-код отсканирован» (картинка скрывается) → три фото: «Подтверждение участия», «Участие подтверждено», «Поисковый запрос выполнен» (запрос назначается случайно и показывается ровно в том виде, в каком его вводить) → «Завершить выполнение». Каждый этап фиксируется кнопкой «Далее», до этого фото можно переснять или удалить крестиком. **Назад** (ТЗ 28.10 §19) — кнопкой «Назад» или по полоске этапов, в том числе к QR-коду: фото, QR и отметка о сканировании сохраняются, вперёд — снова «Далее». Перед каждым шагом вперёд сервер проверяет, что файл фото на месте и не изменился; пропавшее или повреждённое фото останавливает с названием этапа и предложением переснять, ошибка чтения — «повторите». Повторное нажатие не создаёт второе выполнение, альбом не уйдёт в группу дважды. **«⛔ Прервать выполнение»** — на любом шаге, с предупреждением и кнопками «⛔ Да, прервать» / «↩️ Продолжить выполнение»: фото удаляются, в статистику не попадает.
- **Номер задания** — «Алиса #152»: сквозной номер для всех сотрудников и QR, не меняется никогда; пропуски (прерванные) возможны. QR без своего номера показывается как «QR 5».
- **Камера** — только встроенная в приложение (видоискатель Telegram WebView). Если доступ к камере запрещён или клиент её не даёт, приложение говорит об этом; всё, что уже сделано, сохранено на сервере.
- **Фотоотчёты** уходят в группу с темами: владелец пишет `/alice_here` в такой группе, бот — администратор с правом «Управление темами». У каждого сотрудника своя тема, три фото одним альбомом. У каждого фото подпись «Алиса #N · фото K/3 — <этап>» и имя исполнителя ссылкой на профиль; на первом — ещё время МСК, QR, запрос и статус (Telegram показывает подписи альбома при открытии фото, а под альбомом — только если подпись одна; поэтому общий блок на первом фото, а этап — на каждом). На сервере фото лежат только до отправки. Если отправка не удалась, выполнение получает «Не отправлено» с причиной и отправляется повторно каждые 10 минут, кнопкой у сотрудника или — после всех повторов — кнопкой администратора в «Модерации». Если перед отправкой пропал файл фото, выполнение возвращается сотруднику на этот этап. Удалённую тему бот создаёт заново и сообщает администраторам. Одинаковое фото в разных выполнениях подсвечивается модератору — это подсказка, а не доказательство подделки.
- **Модерация** («Админ → Алиса → Модерация»): фильтры по статусу, сотруднику и датам, три фото, запрос, QR, ссылка на сообщение в группе. «Подтвердить» → «Принято, ожидает оплаты», «Отклонить» (причина по желанию, есть шаблоны) → «Отклонено». Решение одно; сотрудник получает «Ваша Алиса #N — принята / отклонена администратором» и где смотреть статус («Работа» → «Алиса»), в теме меняется подпись и появляется ответ «Алиса #N — …». После оплаты подпись меняется на «Оплачено», сотрудник получает номера оплаченных заданий и сумму.
- **Статистика**: у сотрудника — сегодня, неделя и всё время (всего завершено, на модерации, отклонено, принято, оплачено), у админов — по сотрудникам, QR и дням за период. «Всего завершено» — все отправленные.
- **Поисковые запросы** — 166 обычных запросов в `backend/app/resources/alice_queries.txt`; дальше список правится в «Админ → Алиса → Запросы». Одному человеку запрос не повторяется, пока список позволяет.
- **Выплата** («Админ → Выплаты → По «Алисе»», владелец, ТЗ 28.10 §25): за период по каждому QR видно, сколько принято, уже оплачено, ждёт оплаты; вводится, сколько подтвердил отчёт Яндекса. Столько заданий периода этого QR оплачиваются — выбираются случайно, но при повторном открытии те же; остальные задания периода по этому QR получают «Отклонено Яндексом». QR без введённого числа не трогается. Ввести больше, чем ждёт, нельзя. Ставка за выполнение — «Настройки → Ставки» (только владелец), уже проведённые выплаты не пересчитываются. Штрафы и вычеты человека — общий долг: их удерживает та выплата, что идёт первой, — обычная или по «Алисе»; налог на лень здесь не участвует. Проведённая выплата в общем реестре, задания связаны с ней.
- **Штраф за «Алису»** (ТЗ 28.10 §24): в карточке сотрудника → «Штраф» → «За «Алису»», в штрафных единицах, можно указать номер задания. Назначают владелец и администраторы. Виден в истории, удерживается один раз.
- **Удаление задания** (ТЗ 28.10 §23, владелец и администраторы): в «Модерации» → «Удалить задание», с подтверждением и причиной по желанию. Фото с подписью (номер, исполнитель, кто удалил, причина, дата) уходят в чат «Архив», альбом и ответ со статусом удаляются из темы сотрудника (боту нужно право «Удаление сообщений»), задание пропадает из списков и статистики, запись и связи остаются; исполнитель получает сообщение. Если часть не удалась — администратор видит это и нажимает ещё раз: повторяется только недоделанное, второй копии в архиве не будет. Задание из действующей выплаты удалить нельзя — сначала измените или аннулируйте выплату.
- **Цели и события по продукту**: при создании можно выбрать «Считаем принятые выполнения «Яндекс Алисы»» — такую цель и событие видят только люди с доступом. Если человек без доступа, сервер предупредит и предложит «Выдать доступ и создать».

### «Яндекс Плюс» (ТЗ «Яндекс Плюс»)

Отдельный продукт «Работы» на механике «Алисы» (тот же модуль `alice.py`, те же таблицы с полем `product`): свои данные и настройки, общая инфраструктура.

- **Доступ** — отдельный переключатель «Яндекс Плюс» в карточке сотрудника, независимо от «Алисы». Сервер проверяет его на каждом шаге (`/api/work/plus/…`).
- **QR-коды** — «Админ → Яндекс Плюс → QR-коды»: свои QR (название или номер до 60 знаков), назначение, история, архив. У сотрудника — по одному QR на продукт; QR одного продукта никогда не используется в заданиях другого.
- **Выполнение** — «Работа» → «Яндекс Плюс»: QR-код → «QR-код отсканирован» → **одно фото** личного кабинета Яндекс Плюса (состояние подписки и, если показаны, сумма и дата следующего списания) → «Далее» → «Завершить выполнение». Назад по этапам, пересъёмка, «Прервать», повторная отправка — как у «Алисы». Номер задания — общий сквозной: «Яндекс Плюс #153».
- **Группа фотоотчётов** — отдельная: владелец пишет `/plus_here` в группе с темами (бот — админ с правом «Управление темами»). Группа «Алисы» (`/alice_here`) не меняется; одну и ту же группу двум продуктам подключить нельзя. Темы по сотрудникам — свои для каждого продукта. Одно фото уходит обычным сообщением с подписью: «Яндекс Плюс», сотрудник (ссылка), задание, QR-код, дата, время, статус.
- **Модерация, статистика, удаление** — «Админ → Яндекс Плюс» (те же вкладки, без «Запросов»): одно фото, свои шаблоны причин отказа (««Яндекс Плюс»: отклонить»), архив и удаление публикации именно из группы Плюса. В «Решениях» — отдельные строки «📸 «Яндекс Плюс»: …».
- **Деньги** — «Выплаты → По «Яндекс Плюсу»»: та же сверка по QR с отчётом Яндекса, правка версиями и аннулирование; ставка — своя: «Настройки → Ставки → «Яндекс Плюс» за выполнение» (`plus_rate`), отдельно от «Яндекс Алиса» за выполнение» (`alice_rate`); при обновлении она начинается равной ставке «Алисы», выплата хранит ставку, по которой проведена. Штраф — «За «Яндекс Плюс»» (можно указать задание). Выплаты и статистика продуктов не смешиваются.
- **Цели и события** — «Считаем принятые выполнения «Яндекс Плюс»»: считаются только задания Плюса.

**Продукты в целях и событиях (§11).** В формах предлагаются только продукты, которыми автор может управлять: владелец и администраторы — все, тренеры и инструкторы — только те, к которым у них самих есть доступ (`/api/me` → `manageable_products`). Нет ни одного — выбор продукта скрыт. Сервер отклоняет недоступный продукт и в ручном запросе (403 `no_product_access`). Уже созданные цели и события не меняются.

### Ждут решения (ТЗ 28.10 §14)

- У каждого раздела админки — число открытых запросов, на вкладке руководителя — их сумма. Считает один серверный механизм (`app/pending.py`, `GET /api/admin/pending`) теми же правилами, что и списки: один запрос — одно число, просмотр ничего не сбрасывает, только решение. Числа обновляются раз в 30 с, при возврате в приложение и сразу после любого действия.
- Разделы: «Отчёты» (на проверке + неявки), «Дисциплина», «Финансы» (штрафы на согласовании и без суммы), «Онбординг» (новые анкеты и стажировки на проверку), «Команда» (заявки на доступ без анкеты — кандидатов решают только в «Онбординге»), «День» (срочные заявки на сегодня + кто не отметил сегодня и завтра), «События», «Алиса» (модерация и «не отправлено» после всех повторов), «Факт дня» (и просроченные дни старше двух недель).
- Тренер и инструктор видят числа только по тому, что решают сами в своей сети; анкеты, согласование штрафов, «Алиса», факт дня — только владельцу и администраторам. В боте — команда `/pending`.
- Срочная заявка, по которой никто не решил до конца дня, закрывается сама («не подтверждена»), сотрудник получает сообщение.

### «День»: кто не отметился

Вверху «Админ → День» — две вкладки, «Сегодня» и «Завтра» (даты — по часовому поясу проекта): кто не записался и не взял выходной (со статусом «Работаю»; те же правила, что у проверки в 22:00), с пометкой «Не в графике и не на выходном». Руководитель прямо там ставит человеку «Выходной» или «В график» (время, объём, точка); человек получает сообщение. Прошедший день отметить нельзя; отклонённая срочная заявка не мешает отметить.

**«Оштрафовать» (ТЗ 29.10 §6):** та же форма и тот же штраф, что в «Дисциплине» (единицы, причина, файлы; штраф тренера — на согласование). За сегодня — сразу, за завтра — после срока отметки (22:00). Сервер находит нарушение «не отмечен день» этого человека за эту дату (или создаёт его, если проверка в 22:00 ещё не прошла) — у пары «человек + дата» оно одно (уникальный ключ в базе), и штраф назначается только по нерешённому нарушению в одной транзакции: двойное нажатие, повтор запроса, проверка в 22:00 после ручного штрафа и наоборот второго штрафа не дают. Если решение уже есть, кнопки нет — видно, что с нарушением: ждёт решения, штраф назначен / на согласовании / удержан / аннулирован, прощено. Отклонённый штраф снова открывает нарушение — новый штраф только новым действием. Нарушение, записанное в 22:00, остаётся в «Дисциплине», даже если потом руководитель отметил день.

**Напомнить (ТЗ «Яндекс Плюс» §12):** у каждого не отметившегося — «Напомнить», над списком — «📣 Напомнить всем» (сегодня и завтра; владелец и администраторы — всем, тренер — своей сети, инструктор — своим людям; чужой ID сервер отклоняет). Сообщение от бота: «необходимо указать рабочую смену или отметить выходной на завтра (дата)… до {дедлайн} сегодняшнего дня… может быть начислен штраф…» — дата и дедлайн (`daily_mark_deadline`, 22:00 по умолчанию) подставляются сами. Отметившиеся уже не получают; повтор того же нажатия ничего не шлёт второй раз, человеку, которому напомнили про этот день меньше 5 минут назад, повторно не пишется. Результат — сколько дошло, кто пропущен и кому не доставлено (ошибка одного не мешает остальным). Напоминание — не штраф: штрафы идут прежним путём. Над списком — обратный отсчёт «До дедлайна: 3 ч 24 мин» по серверному времени, без перезагрузки; после срока — «Дедлайн наступил». После полуночи «Сегодня/Завтра» сдвигаются сами.

### Шаблоны причин и тексты сообщений (ТЗ 28.10 §2)

«Настройки → Шаблоны причин»: списки по видам действий (штраф, бонус, вычет, пауза, блокировка, отказ кандидату, отмена обучения, отклонение запроса, «Алиса» и др.) — в формах это кнопки, текст можно поправить перед отправкой; в боте — те же кнопки. Обязательна ли причина, решает сервер (блокировка — обязательно). «Настройки → Тексты сообщений»: что бот пишет кандидатам и сотрудникам; слова в фигурных скобках бот подставит сам, «Вернуть исходный» отменяет правку.

### Архивная группа

Создайте закрытую группу, добавьте бота, владелец пишет там `/archive_here` (отключить — `/archive_off`). Туда уходят только деньги, статусы и дисциплина с хештегами для поиска: `#штраф #блок #пауза #роль #доступ` и тег сотрудника вида `#Иван_Петров`. Каждая запись дублируется в таблицу `archive_log`, неотправленные видны с причиной.

### Автоматические сообщения (админ → «Настройки»)

Время и включение каждого сообщения меняются в приложении. Каждое уходит один раз в день, даже если сервер перезапускался, а после долгого простоя устаревшие сообщения не отправляются.

| Сообщение | Кому | По умолчанию |
|---|---|---|
| Напоминание накануне смены: время, точка, кто ещё на точке | сотруднику | 20:00 |
| Распред на завтра | админам | 21:00 |
| «Отметь график на следующую неделю» тем, кто работает и ничего не отметил | сотрудникам | чт 12:00 |
| Запрос факта: «Сколько сделал?» с кнопкой «как план» или своим числом | сотруднику | через 15 мин после конца смены |
| Итоги недели: план и факт по каждому + файл Excel | админам | пн 10:00 |
| Проверка нормы выходов за прошлую неделю → «Дисциплина» | руководителям | пн 10:30 |
| Резервная копия базы файлом | владельцам | 04:00 |
| Напоминание об отметке графика на завтра | тем, кто не отметил | 20:00 |
| Напоминание об обучении | кандидату | накануне 20:00 и утром 08:00 |

Напоминания следуют статусу: «Работаю» — включены, «Не работаю» — бот их не присылает (ТЗ 28.10 §9). С «Не работаю» сервер не даёт записаться и менять смены, начать новое выполнение «Алисы» и отправить заявку в событие; отменить свою смену, сдать отчёт за отработанную смену и довести начатое выполнение можно. Объявления о целях и событиях и недельная проверка нормы выходов таких людей не касаются (если выключить статус уже после проверяемой недели, проверка всё равно будет). Сколько дней человек не работает, видно ему в профиле, а админам и тренерам — в «Команде» и «Сетях».

### Ещё в админке

- **Распред** — «На сегодня», «На завтра» или «📅 Дата» на любой день, прошлый или будущий, с готовым текстом и кнопкой «Скопировать» (ТЗ №21). Тренер видит распред только своей сети, в боте — /raspred_zavtra.
- **Команда** — заявки, назначение админов (только владельцы из `ADMIN_IDS`), закрытие и возврат доступа, ссылка-приглашение в бота.
- **Точки** — справочник точек и лимит людей на точку в день. Если точки заданы, сотрудник выбирает точку из списка и видит, сколько мест занято.
- **Отчёт** — план и факт за период, заработок по плану и по факту, выгрузка в Excel (итоги, смены, штрафы) — файл приходит в бот.
- **Рассылка** — сообщение от бота работающим сейчас, всем сотрудникам или админам; видно, скольким доставлено.

**Факт.** Сотрудник вносит, сколько сделал, в день смены и до 3 дней после — в приложении или ответом боту. Позже факт меняет только админ.

**Изменение смены (ТЗ 27.10).** Время московское, правила считаются для каждой даты отдельно; срок — «Настройки → Отметка графика на завтра» (по умолчанию 22:00).
- До 22:00 накануне — всё свободно: «Выйду» или «Выходной», объём, время, точка, «Беру выходной» и «Передумал, выйду» — сколько угодно раз.
- С 22:00 до 00:00 — только время и точка (сколько угодно раз); объём, отмена и смена статуса закрыты; записаться на завтра нельзя.
- С 00:00 дня смены — ничего, кроме срочной записи «на сегодня» (её подтверждает администратор).
- После ограничений — «Связаться с администратором»: сообщение со сменой и объяснением уходит владельцам, админам и тренеру сети, смена при этом не меняется. В карточке смены — таймер до следующего ограничения. Все проверки — на сервере.
- Окончательной отмены со штрафом и «вернуться один раз» больше нет; старые записи с таким штрафом сохранены.

Все действия проходят через сервер. Повторное нажатие на кнопку не создаёт дубликат: у каждого действия есть ключ, который сервер обрабатывает только один раз. Все события пишутся в журнал `event_logs`.

## Запуск на сервере

Нужен VPS с Ubuntu 22.04/24.04 (1 CPU, 1–2 ГБ RAM, 10+ ГБ диска). Домен не обязателен: без него используется бесплатный `<ip>.sslip.io` (например `203-0-113-5.sslip.io`), который указывает на IP сервера. HTTPS-сертификат при этом настоящий.

Зайдите на сервер под root и запустите установщик:
```bash
bash deploy/install.sh        # из клона репозитория
```
Скрипт проверит доступ к Telegram, включит swap, поставит Docker, спросит токен бота и ID админов, соберёт и запустит всё, поставит ежедневный бэкап базы. Повторный запуск обновляет приложение до свежей версии ветки.

Вручную то же самое: скопировать `.env.example` в `.env`, заполнить и выполнить `docker compose up -d --build`. Админы из `ADMIN_IDS` получают доступ сразу, без заявки.

**Владельцы** (строка `ADMIN_IDS` в `.env`) меняются скриптом, он сам перезапускает бота:
```bash
bash deploy/owners.sh                      # кто владелец сейчас (с именами)
bash deploy/owners.sh add 123456789        # добавить владельца, остальные остаются
bash deploy/owners.sh remove 123456789     # убрать (последнего убрать нельзя)
```
Telegram ID человека видно в приложении: «Админ» → «Команда» → нажать на человека.

**Токен бота** (строка `BOT_TOKEN` в `.env`) меняется скриптом — например, после `/revoke` в @BotFather:
```bash
bash deploy/token.sh          # спросит новый токен (ввод скрыт), проверит его в Telegram, сохранит и перезапустит бота
bash deploy/token.sh check    # какой бот подключён сейчас (сам токен не показывается)
```
Токен не передаётся аргументом, поэтому не остаётся в истории команд. Неверный или отозванный токен скрипт не сохранит. Если токен от другого бота, скрипт спросит подтверждение. База, владельцы и настройки не меняются, прежний `.env` остаётся в `.env.bak`.

База лежит в `./data/bot.db`. Бэкап вручную:
```bash
docker compose exec app python scripts/backup.py /data/backups
```

## Локальная разработка

```bash
# бэкенд
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements-dev.txt
cd backend && ../.venv/bin/python -m pytest          # тесты
BOT_TOKEN=... ADMIN_IDS=... ../.venv/bin/python -m app.main   # бот + API на :8000
#   RUN_BOT=0 — запустить только API без подключения к Telegram

# фронтенд
cd frontend && npm install
npm run dev     # :3000, /api проксируется на :8000
npm run build   # статический экспорт в frontend/out — его раздаёт бэкенд
```

Вне Telegram Mini App покажет «Откройте из Telegram»: без подписанных `initData` API отвечает 401.

## Отличия от ТЗ (осознанные)

- **SQLite вместо PostgreSQL** — людей немного, один процесс пишет в базу, режим WAL. Таблица `daily_summaries` не нужна: итоги дня считаются запросом.
- **Очередь уведомлений не нужна** — API и бот в одном процессе, уведомления отправляются фоном, ответ Mini App их не ждёт.
- **Точка** — свободный текст (как в ТЗ) + быстрые кнопки с уже встречавшимися точками.
- **История** показывает все детали смены прямо в списке, без отдельной шторки.
- **Штраф за нарушение графика** — в штрафных единицах; в журнале финансов хранится и сумма в целых рублях (единицы × ставка на момент назначения). Решение по нарушению принимается в Mini App (нужны комментарий и файлы), в бот приходят сводка и итоговые сообщения.
- Админ может назначить или поменять штраф и одобрить срочную заявку и из Mini App, а не только из бота.
