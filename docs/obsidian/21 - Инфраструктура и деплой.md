# Инфраструктура и деплой

**Обновлено:** 2026-11-18 · **Исходники:** `Dockerfile`, `docker-compose.yml`, `Caddyfile`, `deploy/install.sh`, `deploy/owners.sh`, `deploy/token.sh`, `backend/scripts/backup.py`

## Сервер и пути

Боевой сервер: `root@sasanya.duckdns.org` (SSH-ключ на рабочей машине агента, `BatchMode` проходит без пароля).
Установка — `/opt/bot_sanya`, приложение — https://sasanya.duckdns.org. Рабочая копия для разработки — отдельная папка
на машине агента (клон репозитория).

> [!warning] Из AGENTS.md (жёсткие запреты)
> - **Боевая установка `/opt/bot_sanya`**: её файлы, `.env`, `data/` и контейнеры не трогать руками. Единственный
>   способ выложить изменения — `bash /opt/bot_sanya/deploy/install.sh` по SSH; вручную `docker compose` там не запускать,
>   боевого бота не останавливать, чужие контейнеры/образы не трогать.
> - Секреты (токен бота, ADMIN_IDS, токены GitHub/DuckDNS, ключи API) живут только в `/opt/bot_sanya/.env`; никогда не коммитить и не выводить.
> - Docker локально у агента — только одноразовые контейнеры для проверок (`python:3.13-slim` для pytest, `node:22` для lint/build).

## Образ и контейнеры

- `Dockerfile`: стадия 1 `node:22-alpine` — `npm ci && npm run build` (static export); стадия 2 `python:3.13-slim` —
  `pip install -r backend/requirements.txt`, копия backend + `frontend/out`, `ENV DB_PATH=/data/bot.db MEDIA_DIR=/data/media
  FRONTEND_DIST=/app/frontend/out PORT=8000`, `CMD python -m app.main` из `/app/backend`.
- `docker-compose.yml`: сервис `app` (env_file `.env`, том `./data:/data`, restart unless-stopped) + `caddy:2.8`
  (порты 80/443, том `Caddyfile:ro` + `caddy_data`, Let's Encrypt для `$DOMAIN`, `reverse_proxy app:8000`).

## Установка и обновление

```bash
bash deploy/install.sh    # под root: проверка доступа к Telegram, swap, Docker, вопрос токена и админов, сборка, запуск, ежедневный бэкап
```
Повторный запуск обновляет до свежей версии ветки. `.env` и база сохраняются. Вручную: `.env.example → .env`, `docker compose up -d --build`.
Без домена — бесплатный `<ip>.sslip.io`. Бэкап руками: `docker compose exec app python scripts/backup.py /data/backups`.

## Владельцы и токен

```bash
bash deploy/owners.sh                    # показать владельцев
bash deploy/owners.sh add|remove <TG_ID> # изменить ADMIN_IDS (последнего убрать нельзя), перезапуск
bash deploy/token.sh [check]             # сменить токен бота (скрытый ввод, проверка в Telegram, .env.bak) / показать подключённого бота
```

## Выкладка (порядок из AGENTS.md)

1. Разработка и проверки — [[23 - Тесты и проверки]] (тесты + lint + build зелёные).
2. Коммит (по-русски, что изменилось для пользователя) + **обновление доки** ([[00 - Регламент документации]]) →
   `git push origin claude/schedule-bot-miniapp && git push origin claude/schedule-bot-miniapp:main`.
3. Деплой на боевой — агент запускает сам (решение заказчика 18.11), из своей рабочей копии:
   ```bash
   ssh -o BatchMode=yes root@sasanya.duckdns.org "cd /opt/bot_sanya && bash deploy/install.sh"
   ```
   Скрипт неинтерактивен при повторном запуске: `git fetch` + `reset --hard origin/claude/schedule-bot-miniapp`,
   `.env` и `data/` не трогает, `docker compose up -d --build`, ждёт HTTPS и печатает «Готово!». Сборка — несколько
   минут (фронтенд в Docker), бот коротко перезапускается.
4. Проверка после деплоя (одной командой):
   ```bash
   ssh -o BatchMode=yes root@sasanya.duckdns.org "cd /opt/bot_sanya && git log --oneline -1 && \
     docker compose ps --format '{{.Name}} {{.Status}}' && curl -s -m 5 https://sasanya.duckdns.org/healthz"
   ```
   `git log -1` должен совпасть с запушенным коммитом, оба контейнера `Up`, healthz — `{"ok":true}`.
   Логи при проблемах: `docker compose logs app --tail=50`.
5. Заказчику сообщить: что выложено, коммит, состояние healthz.

## Локальная разработка

```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements-dev.txt
cd backend && ../.venv/bin/python -m pytest
BOT_TOKEN=… ADMIN_IDS=… RUN_BOT=0 ../.venv/bin/python -m app.main   # API без Telegram
cd frontend && npm install && npm run dev   # :3000, /api → :8000
```
