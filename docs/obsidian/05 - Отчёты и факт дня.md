# Отчёты и факт дня

**Обновлено:** 2026-11-17 · **Исходники:** `backend/app/reports.py`, `backend/app/day_actual.py`

## Отчёт о смене (reports.py)

Факт (шт.) + обязательный скриншот. Сдавать можно с 00:00 дня смены (до/после самой смены). У одной смены —
цепочка попыток (`reports.attempt`), итоговый статус живёт на смене в `report_state`.

```
report_state NULL --сдать--> pending_review        (каждый отчёт ждёт проверки, даже факт ≥ план)
               --сдать, команда уже выполнила план--> approved
pending_review --принять--> approved
pending_review --на исправление (комментарий)--> needs_fix --сдать снова--> … (новая попытка, без срока)
pending_review --отклонить + штраф--> rejected
NULL --прошёл срок--> no_show --штраф | без штрафа | внести результат--> решено
любое --внести результат (персонал)--> approved
```

- **Срок сдачи** = `max(00:00 следующего дня, конец смены + 2 ч)`. Напоминание до срока (`report_reminder_lead`),
  после срока смена становится неявкой (`no_shows` в планировщике). Смены до версии отчётов (`reports_since`) неявками не становятся.
- После сдачи сотрудник не меняет сам смену (план фиксируется).
- Скриншоты в Telegram (`file_id`), в приложении — по подписанным ссылкам `/api/media/report/{id}` ([[17 - Уведомления и планировщик]]).
- Формы решений: `POST /api/admin/shifts/{id}/review` (approve|return|fine), `/no-show` (fine|excuse), `/result` (внести результат).
- Штраф за отчёт/неявку — в штрафных единицах, в журнал финансов (`source=report/no_show`), повтор по тому же shift+source невозможен (UNIQUE).
- Решение одно: повтор запроса «Уже решено». Карточки решений в боте помечаются у всех проверяющих.

## Факт дня (day_actual.py)

Общий факт команды за день вводит **только владелец**: «Админ → Факт дня» или `/fakt 480 [ДД.ММ]`.
Общий план = сумма планов состоявшихся смен (`active/restored`).

- **actual ≥ план** → команда выполнила: все ожидающие отчёты с недобором дня получают `approved_team`
  (сотрудникам пуш, в архив «🟢 АВТОМАТИЧЕСКОЕ ОДОБРЕНИЕ»); сданные позже отчёты такого дня принимаются сразу;
  штрафы за недобор дня можно аннулировать (`/api/admin/day-actuals/{day}/annul` — по одному или все).
- **actual < план** → недоборы на ручной проверке.
- Штраф за недобор нельзя назначить, пока факт не введён, и нельзя при выполненном плане (штрафы за неявку и недостоверный отчёт — всегда).
- Каждое изменение — в `day_actual_log`; бейдж «Факт дня» + напоминания владельцам вечером (за сегодня) и утром (за вчера).
- «Просроченные» дни: `pending.overdue_actual_days` — дни со сменами без факта старше `LOOKBACK_DAYS` (2 недели), считаются отдельно.
