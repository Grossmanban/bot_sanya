# База данных и миграции

**Обновлено:** 2026-11-19 · **Исходники:** `backend/app/db.py` (миграция 50 — «скрыть» в онбординге)

## Устройство

SQLite, режим **WAL**, `synchronous=NORMAL`, `busy_timeout=5000`, `foreign_keys=ON`. Один файл: `DB_PATH`
(боевой — `/data/bot.db` в томе `./data`). Подключение `connect(path)` создаёт каталог, выполняет базовый `SCHEMA`
(три таблицы первой версии) и накатывает миграции.

**Счётчик версий** — `PRAGMA user_version`. `migrate()` выполняет `MIGRATIONS[version:]` по порядку, каждая в своей
транзакции `BEGIN IMMEDIATE` с `PRAGMA foreign_keys=OFF` (пересборки таблиц требуют), после каждой — `foreign_key_check`.

> [!warning] Железные правила миграций (нарушение = фатально)
> 1. `MIGRATIONS` — **только дописывать в конец**, существующие никогда не менять (боевые базы уже прошли их).
> 2. `_run_script` делит SQL по `;` и выкидывает строки-комментарии `--`. **Запрещено `;` внутри SQL-комментариев** и многострочные комментарии.
> 3. CHECK/UNIQUE в SQLite нельзя менять на месте — таблица пересобирается (create-copy-drop-rename) с сохранением id и счётчика `sqlite_sequence` (примеры: `_rebuild_users_and_shifts`, `_widen_check`, `_unmarked_days`, `_goal_kinds`).
> 4. Миграция с данными — Python-функция (элемент списка `MIGRATIONS` может быть `str` или callable).
> 5. После добавления миграции — обновить счётчик ниже и таблицу затронутых таблиц.

- `reports` — попытки отчёта (shift_id, attempt UNIQUE), статус `pending_review/approved/auto_approved/approved_team/rejected_penalty/rejected_retry`, фото `photo_file_id`. См. [[05 - Отчёты и факт дня]].
- `day_actuals` (день → общий факт/план/met) + `day_actual_log` (история изменений).

### Деньги (миграции 8, 14, 16, 37)

- `financial_transactions` — единый журнал: type `fine/bonus/deduction/payout_offset`, статус `draft/pending_admin_approval/active/paid/cancelled/offset/rejected`, source `manual/final_cancel/report/no_show/payout/attendance`, штрафные единицы `pieces+rate`, для «Алисы» `product/alice_task_id`, связь `linked_tx_id` (часть тренера). Частичный UNIQUE (shift_id, source) среди живых. См. [[06 - Финансы, ставки и вычеты]].
- `attendance_violations` — дисциплина: kind `weekly/unmarked`, UNIQUE (user, kind, week_start_date), статус `pending/penalized/waived`. См. [[15 - Дисциплина]].

### Сети и выплаты (миграции 9, 10, 16, 27, 37)

- `networks` — сеть, `trainer_id`, лестницы `ladder/instructor_ladder` (+period, counts_trainer), `rate_base`.

- `payout_batches` (rates снапшот, proof, `product`, version, аннулирование) + `payout_items` (штуки, база, комиссии, копилка `lazy_units/lazy_before`, voided) + `payout_versions`. См. [[07 - Выплаты и реквизиты]].

### Цели и события (миграции 12, 13, 17, 21)

- `events` (mode `first_to_reach/accumulative`, version, visibility, product) + `event_entries` (annulled) + `event_entry_messages` (карточки заявок у проверяющих). См. [[14 - Цели и события]].

- `invite_links` (kind `ref/owner`, token, ttl, uses, revoked/replaced) + `invite_uses` + `access_attempts` (+ restore-поля ТЗ 30.10 §3) + `referral_hits`. См. [[09 - Рекрутинг и доступ]].

### «Работа»: Алиса/Плюс (миграции 29, 36, 37, 39, 40)

- `product_access` — доступ к продуктам (живой UNIQUE user+product).

- `alice_topics` — тема сотрудника на продукт: PK (user_id, product). См. [[13 - Работа, Алиса и Яндекс Плюс]].
