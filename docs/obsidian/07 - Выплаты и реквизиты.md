# Выплаты и реквизиты СБП

**Обновлено:** 2026-11-18 · **Исходники:** `backend/app/payouts.py`, `backend/app/rates.py` (`trainer_share_manual` / `instructor_share_manual`), `backend/app/profiles.py` (реквизиты), `backend/app/alice.py` (выплата по «Алисе»/«Плюсу» — см. [[13 - Работа, Алиса и Яндекс Плюс]])

## Реквизиты (`payment_profiles` + `payment_profile_log`)

Телефон СБП, банк из списка (или «Другой банк» + `bank_name`), ФИО получателя. Видят сотрудник и владелец (остальным
номер замаскирован). Изменение сотрудником (и первое заполнение) — заявка `profile_requests(kind='payment')` на
одобрение **владельцу**; до одобрения выплаты идут по прежним. Владелец меняет сразу. Каждое изменение — в журнал.
**Выплата человеку без одобренных реквизитов не фиксируется** — мастер называет, кого убрать.

## Мастер выплаты (только владелец, «Админ → Выплаты»)

1. **Параметры**: период, сеть, ставки на эту выплату (снапшот в `payout_batches.rates`).
2. **Команда и суммы** (18.11, `POST /api/admin/payouts/preview`, `manual: true`): вся команда списком, у каждого —
   **галочка** (включён — подсвечен; по умолчанию снята у не работавших в период) и **пустое поле суммы** — владелец
   вписывает каждому по отчёту бухгалтера. Под полем: «≈ N шт.» (сумма ÷ ставка человека: личная → общая), справка
   «за период: план X / факт Y шт.», расчёт по отчётам (`auto_pay`), копилка, бонусы/штрафы/вычеты. Штуки из сумм идут
   в «команду» тренера/инструктора: агрегатная комиссия `trainer_share_manual`/`instructor_share_manual` — объём включённых
   × ставку (личная комиссия → лестница → общая) в пределах дельты; посуточной разбивки у ручной выплаты нет.
   Тренер с суммой 0 получает командные; включённый без суммы и без начислений → 422 `amount_required`.
   «Пересчитать» шлёт введённые суммы и галочки на сервер — комиссии и зачёт приходят оттуда. Прямо в строке можно
   начислить бонус/штраф/вычет. План/факт периода — справка, из смен не платится.
   Владелец на сменах получает за свои штуки по своей ставке; за свои сети тренерских нет.
   **Заработок владельца** = штуки из сумм включённых × `revenue_per_piece` − всё выплаченное.
   *API без `manual`/`amount` (до 18.11) считает по-старому — из принятых штук; `commit`/`edit` без ключа `amount`
   в choices тоже (легаси-режим).*
3. **Фиксация** (`POST /api/admin/payouts`, идемпотентна): пересчёт на сервере по тем же суммам; зачитываются **все**
   активные бонусы/штрафы/вычеты независимо от даты — сначала вычеты, потом штрафы (старые первыми); не поместившийся
   штраф съедает остаток выплаты, его хвост остаётся активным с меньшей суммой ([[06 - Финансы, ставки и вычеты]]).
   Учтённые записи → `offset` с `payout_id`. Копилка списывается (ручная выплата — целиком). Суммы и штуки пишутся в
   `payout_items.entered_amount/entered_units` (миграция 44; NULL — считалось из смен, как раньше).
   Владельцу в бот: Excel-реестр и **список для банка обычным текстом** — группировка по банкам, каждый человек блоком
   «ФИО / телефон / сумма» на отдельных строках (долгое нажатие копирует одно поле), итог по банку и «Всего к выплате»
   (`bank_text`); кнопка «Список для банка» копирует тот же текст. В архив ведомость `#выплата` («свои N шт. + команда M шт.»);
   сотрудникам суммы.

**Сброс копилок налога на лень** (18.11): `POST /api/admin/lazy-pool/reset` (владелец, кнопка в «Настройках → Ставки»
с подтверждением) — обнулить накопленное всем и считать с сегодняшнего дня. Нужен после смены порога.

**«Заполнить по фото»** (18.11): в мастере на шаге «Команда и суммы» кнопка (видна при настроенном `OCR_BASE_URL`,
флаг `ocr` в `GET /api/admin/payouts`). Фото ведомости бухгалтера уходит в модель-зрения — локальный opencode-сервер
(`OCR_KIND=opencode`: сессия → промпт с data-URI → опрос сообщений → удаление сессии) или любой OpenAI-совместимый
API (`backend/app/ocr.py`, настройки — [[22 - Настройки приложения]]), ответ чистится (шапки, «Итого», строки
«тренерские» отбрасываются и показываются отдельно), имена нечётко сопоставляются команде (порядок слов, инициалы,
опечатки; при выбранной сети — только её люди). Диалог «Распознано»: строка → наш человек (селект: матч → кандидаты → вся команда; в селекте только «— пропустить —»
и имена), несопоставленные подсвечены, «Подставить» / «Другое фото» / «Закрыть». Диалог выше таббара (z-60,
нижний отступ) — кнопки не перекрываются; результат держится в мастере: случайно закрыл — кнопка «Показать
распознанное» откроет его снова без повторного распознавания (новое фото — «Другое фото»). «Подставить» заполняет
суммы и включает галочки — фиксирует по-прежнему владелец.
`POST /api/admin/payouts/parse-photo?network_id=` — raw-картинка, в БД ничего не пишется.

Запрещены пересечения периодов по одним людям с существующей выплатой (мастер называет, с какой).

## Изменение и аннулирование (ТЗ 28.10 §25)

- **Изменить** (`/{batch_id}/edit`): та же выплата (номер не меняется, дубликата нет), прежняя версия в `payout_versions`;
  суммы предзаполнены из зафиксированной версии; правка без сумм пересчитает по-старому (легаси). Удержания пересчитываются
  заново, каждое по одному разу. По «Алисе»/«Плюсу» — числа Яндекса по QR.
- **Аннулировать** (`/{batch_id}/annul`, с причиной): статус `annulled`, в «Архив» реестра; штрафы/вычеты снова долгом,
  копилка возвращается, задания «Алисы» снова ждут оплаты. Если «деньги уже переведены» — каждому вычет
  «Переплата по аннулированной выплате №…». Ничего не удаляется. Менять/аннулировать можно только **последнюю** выплату этих людей.
- Повторное «Зафиксировать» возвращает ту же выплату без повторной рассылки.
