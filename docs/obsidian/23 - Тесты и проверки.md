**Обновлено:** 2026-11-18 · **Исходники:** `backend/tests/`, `backend/requirements*.txt`, `AGENTS.md`

## Обязательный минимум перед каждым коммитом

```bash
# бэкенд (один раз):
python3 -m venv .venv && .venv/bin/pip install -q -r backend/requirements-dev.txt
cd backend && ../.venv/bin/pytest -q          # все тесты

# фронтенд (нужен Node 22):
cd frontend && npm ci && npm run lint && npm run build
```

На боевом сервере (Python 3.14, нет Node) — Docker только в рабочей копии: `docker build -t bot_sanya-dev .`,
одноразовые `python:3.13-slim` (pytest) и `node:22` (lint). `docker compose` не запускать. Результат проверок сообщать
честно; новая логика = новые тесты по образцу соседних файлов.

## Хорошие практики при доработках

- Тесты используют `auth.sign_init_data` для подписи запросов и `sqlite :memory:` — быстро и изолированно.
- Идемпотентность: тесты повторяют мутацию с тем же ключом и ждут `changed=False`.
- Миграции накатываются на пустой БД в `conftest`; при изменении `MIGRATIONS` проверить upgrade снапшота боевой базы
  нельзя — поэтому правило «только дописывать в конец» ([[02 - База данных и миграции]]).

## Чек-лист перед коммитом (агент)

1. `pytest -q` зелёный; новые тесты на новую логику.
2. `npm run lint && npm run build` без ошибок.
3. Дока обновлена ([[00 - Регламент документации]]) — страницы доменов + справочники + даты «Обновлено».
4. README обновлён, если менялось видимое поведение.
5. Секретов в диффе нет. Коммит по-русски. Пуш: `git push origin claude/schedule-bot-miniapp && git push origin claude/schedule-bot-miniapp:main`.
