# Роли и права

**Обновлено:** 2026-11-17 · **Исходники:** `backend/app/permissions.py`, `backend/app/pending.py`

## Роли

Единственное место правил — `permissions.py`. Владелец определяется по `ADMIN_IDS` из `.env` (не по полю БД).

| Роль | Кто это | Сфера |
|---|---|---|
| `owner` (Владелец) | Telegram ID в `ADMIN_IDS`, может быть несколько | Всё, включая деньги, блокировки, роли, сети, факт дня |
| `admin` (Администратор) | назначает владелец (`users.role='admin'`) | Все сотрудники: смены, отчёты, штрафы сразу, паузы, рассылки, настройки. Без денег/блокировок/ролей |
| `trainer` (Тренер) | назначает владелец; ведёт одну сеть (`networks.trainer_id`) | Только своя сеть (включая людей инструкторов). Штрафы — на согласование |
| `instructor` (Инструктор) | назначает владелец | Только закреплённые (`users.instructor_id`). Смены, отчёты, паузы; штрафы — на согласование |
| `employee` (Сотрудник) | после одобрения | Свой график, отчёты, баланс |

Ключевые функции: `role_of()` (owner>role из БД), `is_staff()` (есть панель), `sees_everyone()` (owner+admin),
`manages(actor, target)` — инструктор: своим по `instructor_id`; тренер: своей сети по `led_network_id` (сеть, где он trainer_id).

## Матрица возможностей `CAN`

`can(actor, capability, target)`: роль в списке + (если указан target) `manages(actor, target)`. В Mini App список
приходит в `GET /api/me` → `capabilities` (фронт скрывает разделы, сервер всё равно проверяет).

| Capability | Роли | Что открывает |
|---|---|---|
| `money` | owner | вычеты, выплаты, погашение штрафов, реквизиты чужие |

| `roles` | owner | назначение ролей |
| `global_actual` | owner | общий факт дня (`/fakt`) |
| `networks` | owner | управление сетями |

| `approve_fines` | owner, admin | решение по штрафам тренеров |

## Состояния аккаунта (влияют на доступ)

- `status`: `pending` (заявка/анкета) → `approved` / `rejected`. Отклонённый молчит.
- `account_state`: `active` / `paused` (пауза с причиной: запись закрыта) / `blocked` (бот и приложение закрыты полностью — `block_guard` в боте, 403 в API; человек исключается из рабочих групп).
- `work_status`: `working` / `not_working` — «Не работаю» закрывает запись смен, новые выполнения «Алисы», заявки в события; напоминания не идут. Сколько дней в статусе — `work_status_at`, `status_days`.

## «Ждут решения» (pending.py)

`GET /api/admin/pending` и команда бота `/pending` — одни и те же счётчики `pending.counts(conn, viewer)`.
Правило «один запрос — один ключ»: просмотр ничего не сбрасывает, только решение; человек с нарушением за день
считается в «Дисциплине», а не в «Дне»; pending-человек с анкетой — «Онбординг».

Ключи: `review`, `no_show`, `violations`, `urgent`, `unmarked` (сегодня+завтра), `events_pending`, `fines_pending`,
`fines_draft`, `registrations`, `onboarding_new`, `internship_review`, `training_requests`, `profile_changes`,
`payment_changes`, `actual_missing`, `actual_overdue`, `alice_moderation/failed`, `plus_moderation/failed`.
Область видимости — `scope()`: owner/admin все, тренер/инструктор только свои.
