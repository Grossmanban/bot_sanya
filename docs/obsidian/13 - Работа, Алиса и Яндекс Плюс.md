# «Работа»: Яндекс Алиса и Яндекс Плюс

**Обновлено:** 2026-11-17 · **Исходники:** `backend/app/alice.py`, `backend/app/products.py`

## Продукты

Один модуль `alice.py` на два продукта: `alice` («Яндекс Алиса», 3 фото + поисковый запрос) и `plus` («Яндекс Плюс»,
1 фото личного кабинета). Таблицы общие с полем `product`; доступ (`product_access`) и QR у каждого свои; QR одного
продукта в заданиях другого не используется. Конфиг продуктов — `alice.KINDS` (имя, команды группы, ставки-ключи).

- Доступ — переключатели в «Команда → Работа: продукты» (owner/admin), журнал изменений; сервер проверяет на каждом шаге
  (`/api/work/{product}/…`), закрытие доступа блокирует новое, история остаётся.
- Вкладка «Работа» видна только тем, у кого есть доступ хотя бы к одному продукту (`GET /api/me → products`);
  `manageable_products` — продукты, которые автор может привязывать к целям/событиям (тренеры/инструкторы — только свои).

## Выполнение

Этапы (step 0–4): QR на экране → «QR-код отсканирован» → фото по этапам (у «Алисы» 3: «Подтверждение участия»,
«Участие подтверждено», «Поисковый запрос выполнен» — запрос случайный из списка, показывается как вводить; у «Плюса» 1).
Каждый этап фиксируется «Далее»; до этого фото можно переснять/удалить. **Назад** — к любому этапу и к QR, данные сохраняются.
Перед шагом вперёд сервер проверяет файл фото (не пропал/не изменился). Одно активное выполнение на (user, product).
«⛔ Прервать» — фото удаляются, в статистику не попадает (`abandoned`).

- **Номер задания** сквозной на оба продукта: «Алиса #152», «Яндекс Плюс #153» — не меняется никогда.
- Камера — только встроенная; отказ камеры объясняется, сделанное сохранено на сервере.
- Поисковые запросы «Алисы»: `backend/app/resources/alice_queries.txt` (166 шт.) → правка в «Админ → Алиса → Запросы»;
  одному человеку запрос не повторяется, пока список позволяет.

## Публикация и модерация

Фото уходят альбомом в **форум-группу** продукта (свои группы: `/alice_here`, `/plus_here`; одну группу двум продуктам
нельзя; бот — админ с правом «Управление темами»; тема на человека и продукт — `alice_topics`). Подписи: номер, фото K/3,
этап, имя-ссылка; на первом — время МСК, QR, запрос, статус. На сервере фото лежат только до отправки (`temp_path`).

Статусы: `in_progress → sending / send_failed → moderation → rejected | accepted («Принято, ожидает оплаты») → paid`
+ `abandoned / yandex_rejected / deleted`. Неудачная отправка — честный статус «Не отправлено», повторы каждые 10 минут
(до 20 попыток), затем кнопка админа. Один отправитель на альбом (`send_claimed_at`). Удалённую тему бот создаёт заново.
Одинаковое фото в разных выполнениях (sha256) — подсветка модератору.

Модерация («Админ → Алиса/Яндекс Плюс → Модерация»): фильтры, фото, ссылка на сообщение. «Принять» / «Отклонить» (причина
из шаблонов `alice_reject`/`plus_reject`). Решение одно; сотрудник получает уведомление; подпись в теме меняется; после
оплаты — «Оплачено». «Модерация → Все» — все статусы, новые сверху.

## Удаление задания (§23)

«Удалить задание» (owner/admin): фото с подписью (номер, исполнитель, кто удалил, причина) → чат «Архив», альбом и ответ
удаляются из темы (нужно право «Удаление сообщений»), задание пропадает из списков/статистики, запись и связи остаются.
Повтор — только недоделанное. Задание из действующей выплаты удалить нельзя.

## Деньги

- **Выплата по продукту** («Выплаты → По «Алисе» / По «Яндекс Плюсу»», owner): за период по каждому QR — принято/оплачено/
  ждёт; владелец вводит, сколько подтвердил Яндекс. Столько заданий этого QR периода оплачиваются (выбор случайный, но
  стабильный при повторном открытии), остальные — `yandex_rejected`. Ввести больше ждущего нельзя. Ставка — своя на продукт
  (`alice_rate` / `plus_rate`, владельцы; выплата хранит использованную ставку). Общий долг (штрафы/вычеты) удерживает
  та выплата, что идёт первой — обычная или продуктовая. Правка версиями и аннулирование — как у обычных выплат ([[07 - Выплаты и реквизиты]]).
- **Штраф за продукт**: «Штраф → За «Алису» / За «Яндекс Плюс»» — в штрафных единицах, можно с номером задания; owner/admin.
- **Статистика**: у сотрудника — сегодня/неделя/всё («всего завершено» = все отправленные); у админов — по людям, QR, дням.
