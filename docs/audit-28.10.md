## 1. Карта механизмов по разделам ТЗ

Условные обозначения: **Есть** — что уже работает, **Доработать** — что расширяем, **Новое** — чего нет совсем.

### §1. Общие требования
- **Есть:**
  - **Права** — одно место, `backend/app/permissions.py`. Там карта `CAN`, функции `can()` и `manages()`.
  - **Проверки в API:** `current_user`, `staff(cap)` и `require()` в `api.py:543-571`. Сервисы дополнительно перечитывают актуальную роль через `_fresh_actor` (`services.py:369`).

### §17. Ссылки на Telegram-профили
- **Есть:**
  - Telegram ID хранится как `INTEGER`. Кандидаты — тоже строки `users`, поэтому ID у них есть. Случаев, где вместо Telegram ID передаётся внутренний ID, **не нашёл**.
  - Помощники на бэкенде: `who`, `handle`, `name_handle` и ещё 5 мест со своими ссылками `tg://user`.
  - На фронтенде **два** помощника: `openProfile` и `openChat` (`telegram.ts:95-122`, `:244-254`).
  - `Notifier.profile_card` пишет «Нажмите на имя, чтобы открыть профиль» и добавляет кнопку `tg://user?id`.
- **Первопричины, почему не работает:**
  1. Ссылка-упоминание `tg://user?id` в тексте кликабельна, **только если человек писал боту и у него не включена приватность пересылки**. Иначе Telegram показывает просто текст: «нажмите на имя», а имя не нажимается.
  2. Кнопка `url=tg://user?id` падает с ошибкой `BUTTON_USER_PRIVACY_RESTRICTED`. Запасной вариант отправляет **тот же текст** «нажмите на имя», только без кнопки.
  3. В Mini App `openTelegramLink` принимает только `t.me`, поэтому `openChat` делает `window.location.href = "tg://…"`, и во встроенном браузере Telegram на iOS/Android это ничего не делает. Так не работают кнопки «Открыть в Telegram» и «Написать» у людей без username.
- **Доработать:**
  - один помощник на бэкенде и один на фронтенде;
  - честный запасной вариант: «профиль скрыт настройками», ID с кнопкой «Копировать», не показывать кнопки, которые не работают;
  - ссылку на ФИО добавить в подписи «Алисы».

### §25. Выплаты: мастер, реестр, история «Алисы»

  - отдельно **по каждому QR**, только статус `accepted` («Принято, ожидает оплаты»);
  - `completed_at <= конец периода`, **начало периода не учитывается**;
  - порядок `ORDER BY completed_at, id` — **сначала самые старые**, это ранее согласованный порядок;
  - оплачиваются первые N, где N — сколько подтвердил Яндекс;
  - **остальные остаются «Принято, ожидает оплаты»** до следующей сверки. Статуса «Отклонено Яндексом» нет, случайного выбора нет;
  - ввести больше, чем ждёт, нельзя.
- **Модель выплат:** `payout_batches` (`status CHECK IN ('processed')` — других статусов нет), `payout_items` (снимок по человеку).
  - Удержания: `financial_transactions.status='offset'` + `payout_id`. При этом **затираются** `decided_by` / `decided_at`.
  - Копилка налога на лень **не хранится**: она пересчитывается из `SUM(payout_items.lazy_units)`.
  - Обычная выплата **никак не связана со сменами**: какие смены оплачены, не записано.
- **Нет:** редактирования, аннулирования, статусов выплаты, «Архива» выплат, списка заданий в карточке выплаты.
- **Найденные ошибки:**
  - повтор «Зафиксировать» с тем же ключом возвращает **последнюю выплату любого вида** без `items`, и `bank_text()` падает (`payouts.py:317-318`);
  - повтор выплаты «Алисы» повторно рассылает уведомления (`alice.py:719`, `api.py:964`);
  - обычные выплаты с пересекающимися периодами оплачивают одни и те же штуки **дважды**.

Кто «тренер» в «Обучении».** Сейчас «Тренер» — это роль **тренера сети** (вкладка «Админ», права на сеть), а тренером кандидата может быть любой сотрудник. **Предлагаю:** доступ к «Обучению» — персональный (как доступ к «Работе»), выдаётся автоматически при назначении тренером кандидата, роль не меняется. ### «Алиса» (§18–§25)

  Учитывать ли начало периода?
- **В51. Редактирование выплаты.** Что можно менять после фиксации? **Предлагаю:**
  - «Алиса»: количество по каждому QR, отсюда состав заданий и суммы;

- **В52. Аннулирование.** **Предлагаю:** только владелец, обязательная причина. В «Выплатах» появляется вкладка «Архив». Запись `#выплата #аннулирование` уходит в архивный чат.

## 4. План этапов (порядок по §29)

После каждого этапа:
- тесты (`pytest`) и новые тесты на новую логику;
- `npm run lint`;
- `docker build` — после ответа на О1;
- коммит, пуш в `claude/schedule-bot-miniapp` и `main`;
