# ТЗ «Яндекс Плюс» и доработки — отчёт (29.10.2026)

Исходное ТЗ — заметка «ЯНДЕКС ПЛЮС тз». Миграция базы 38 → 39 (только добавляет поля и индексы, темы переносятся
как темы «Алисы»; на копии боевой базы: 13 заданий, 1 QR и 1 тема стали `alice`, integrity ok).

## Как сделано (без параллельных систем)

«Яндекс Плюс» работает на том же модуле `alice.py` и тех же таблицах: у `alice_qr`, `alice_tasks`, `alice_topics`
появилось поле `product` (`alice` | `plus`). Описание продукта — `alice.KINDS`: название, этапы фото (у Плюса один),
нужен ли поисковый запрос, ключ группы, команда подключения, тег архива. Все функции (старт, этапы, фото, назад,
прервать, отправка, повтор, модерация, статистика, сверка и выплата, удаление с архивом) принимают продукт или берут
его из задания. Маршруты API — те же, продукт в пути (`/api/work/{alice|plus}/…`) или в `?product=` для админки.

| Пункт ТЗ | Где |
|---|---|
| §2–3 отдельный продукт, независимый доступ, проверка на сервере | `products.PRODUCTS`, `products.require` в каждом шаге |
| §4 свои QR, отделены от «Алисы», название до 60 знаков | `alice_qr.product`, `assigned_qr(…, product)`, `assign` снимает прежний QR только своего продукта |
| §5 сценарий с одним фото | `PLUS_STAGES`, `last_step()`; экран «Работа» общий (`work-screen.tsx`) |
| §6 прерывание и навигация | те же `goto` / `abandon` / ключи идемпотентности; одно активное задание на человека и продукт |
| §7.1 отдельная группа | `/plus_here`; `forum(conn, product)` хранит `plus_chat_*` отдельно; одну группу двум продуктам подключить нельзя |
| §7.2 темы | `alice_topics (user_id, product)`; удалённая тема пересоздаётся, админы получают сообщение |
| §7.3–7.4 публикация и подпись | одно фото — `send_photo` (альбом в Telegram — только 2–10 фото); подпись: продукт, сотрудник, задание, QR, дата, время, статус |
| §7.5 уведомления | принято/отклонено, оплачено, удалено, QR назначен/снят, фото пропало, «Решения» — с названием «Яндекс Плюс» |
| §7.6 удаление и архив | тот же механизм; ищется по сохранённым chat/message id задания; тег `#плюс` |
| §8 модерация | «Админ → Яндекс Плюс»; свои шаблоны причин `plus_reject` |
| §9 деньги | сверка по QR и выплата `product = 'plus'`, правка версиями и аннулирование — общие; штраф `product = 'plus'` с проверкой задания; ставка — своя `plus_rate` (отдельно от `alice_rate`, миграция 40 копирует текущую ставку «Алисы») |
| §10 история, статистика, цели | всё фильтруется по продукту; цели «Яндекс Плюс» считают только его задания |
| §11 продукты в целях и событиях | `products.manageable` / `require_manageable` (сервер), `manageable_products` в `/api/me`, фильтр в формах |
| §12 напоминания и отсчёт | `POST /api/admin/day/{day}/remind`, `violations.mark_deadline_info`, «Напомнить» / «Напомнить всем» и обратный отсчёт в «День» |

## Решения, которые стоит подтвердить

1. **Ставка.** По просьбе заказчика сделана отдельная настройка «Яндекс Плюс» за выполнение (`plus_rate`) рядом со ставкой «Алисы»; после обновления она равна текущей ставке «Алисы».
2. **Дедлайн в напоминании** берётся из настройки `daily_mark_deadline` (сейчас 22:00), а не 20:00 из примера ТЗ.
3. **Код продукта** — `plus`, команда группы — `/plus_here` (по образцу `/alice_here`; в ТЗ он назван `/alisa_herya`).
4. Для отметки «QR отсканирован → фото → Далее → Завершить» сохранён шаг проверки перед завершением, как у «Алисы».
