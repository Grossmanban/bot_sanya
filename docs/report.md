## 2. Как устроено

- **Один процесс**: бот (aiogram 3) + API (FastAPI) + Mini App (Next.js + shadcn/ui, статическая сборка) + встроенный планировщик.
- **SQLite** в режиме WAL, транзакции, миграции с проверкой целостности связей.
- **Безопасность**: подпись Telegram (initData) на каждый запрос Mini App; фото — по подписанным ссылкам с ограниченным сроком, своя подпись на каждый вид фото.
- **Без дублей**: у каждого действия ключ идемпотентности, повторное нажатие ничего не повторяет. Все события — в журнале `event_logs`.
- **Ничего не удаляется физически** — только статусы «удалена», «аннулирован», «в архиве».
- **Развёртывание**: Docker + Caddy с HTTPS, установщик `deploy/install.sh` (бесплатный домен sslip.io, ежедневный бэкап).
- **Секреты** (токен бота, ID владельцев) — только в `.env` на сервере, в git не попадают.

## 3. Что сделано

### Основа
- Регистрация через бота: `/start` → ФИО → заявка админам с кнопками «Принять / Отклонить» → приветствие и кнопка «Открыть график».
- График в Mini App: неделя пн–вс, статусы дней, коллеги на день, запись «с–до», точка, объём, «налог на лень», план заработка, «Не выхожу».
- Жизненный цикл смены: срочная запись на сегодня ждёт решения админа; отмена → одно восстановление → окончательная отмена со штрафом; одно изменение смены.
- Профиль: «Работаю / Не работаю», история, штрафы, ставки.
- Админка: распред на завтра с копированием, смены на любой день, статистика, ручная правка с причиной, точки с лимитом людей, Excel-выгрузка.
- Автосообщения: напоминание накануне, распред админам, «отметь следующую неделю», запрос факта, итоги недели, бэкап базы.
- Дизайн «Выход»: светлая и тёмная тема, телефон и десктоп.

### ТЗ v9.1
1. **Роли и доступ** — владелец, администратор, тренер, сотрудник; права в одной таблице для API, бота и интерфейса. Пауза с причиной, блокировка (только владелец). Архивная группа `/archive_here` с хештегами и журналом `archive_log`.
2. **Отчёты о смене** — факт и обязательный скриншот (бот или приложение); автоприём при выполнении плана, иначе проверка: принять / на исправление / штраф. Срок сдачи, напоминания, сводка админам, неявки с решением.
3. **Общий факт дня** — ввод в приложении или `/fakt 480`; при выполнении командой плана — автоприём отчётов и аннулирование штрафов за недобор; напоминания владельцам, история изменений.
4. **Финансы** — единый журнал штрафов, бонусов и вычетов со статусами; штраф тренера — через согласование владельца; аннулирование с причиной, погашение разом, баланс; перенос старых штрафов.
5. **Сети и тренеры** — сети, назначение тренера, перевод людей; тренер видит только свою сеть.
6. **Выплаты** — реквизиты СБП с журналом изменений; мастер выплаты в 3 шага (база + бонусы → вычеты → штрафы, остаток в долг); реестр, текст для банка, Excel.
7. **Рассылки** — по статусу, ролям, сети и конкретным людям, с фото; «Я ознакомился», список непрочитавших, напоминание одной кнопкой.
8. **Цели** — личные, командные, сетевые; норма на каждого или общая; «Участвую», уведомление о выполнении.
9. **Живые события** — «Гонка до цели» и «Кто больше»: таймер, приз, живой рейтинг, заявки со скриншотом, ограничение попыток, автоматические итоги.

### Пункт 12.4. Нарушения графика
- Норма выходов в неделю в «Настройках» (по умолчанию 3 дня); проверка прошлой недели каждый понедельник в 10:30 и вручную. Одна заявка на человека и неделю, сводка руководителям.
- Раздел «Дисциплина»: ФИО, сеть, неделя, требование, факт, даты пропусков и две кнопки:
  - **Штраф** — сумма, причина (подставлен шаблон), до 5 доказательств; штраф попадает в журнал финансов;
  - **Снять нарушение** — обязательное основание, до 5 документов; деньги не трогаются.
- Одно решение на заявку (повтор — «Заявка уже обработана»).
- Подробное сообщение сотруднику по шаблону ТЗ с файлами и копия в архив (`#нарушение #штраф` / `#нарушение #оправдание`).
- Тренер — только своя сеть, его штраф ждёт согласования владельца; при отказе нарушение снова ждёт решения.

## 4. Как проверялось
- 89 автотестов: логика, права каждой роли, защита от повторов, API, расписание, тексты уведомлений.
- Обновление старой базы (версия 5 → 14): данные и номера записей сохраняются, проверки целостности чистые.
- Фронтенд: проверка типов, линт, сборка.
- Скриншоты каждого экрана в двух размерах и двух темах, найденные проблемы вёрстки исправлены.

## 5. Проверено только в тестах и превью (без живого Telegram)
- Кнопки и диалоги в боте: решения по отчётам, согласование штрафов, «Я ознакомился», «Участвую», заявки на события.
- Доставка фото через Telegram (в превью — локальное хранилище), альбомы до 5 фото в нарушениях.
- Срабатывание задач по расписанию в реальном времени и работа реальной архивной группы.

## 6. Что сделать на сервере
1. Резервная копия `data/bot.db`, затем `git checkout main && git pull` (или повторно `deploy/install.sh`).
2. Проверить, что миграции прошли и старые штрафы видны в «Финансах».
3. Открыть Mini App под владельцем, тренером и сотрудником — каждый видит только своё.
4. Пройти сценарии: отчёт → факт дня; штраф тренера → согласование; рассылка с подтверждением; событие; тестовая выплата; «Дисциплина» — штраф и снятие с фото.
5. До ближайшего понедельника проверить норму выходов в «Настройках».
6. Подключить архивную группу (`/archive_here`), сделать `main` веткой по умолчанию на GitHub.
7. После тестов отозвать и заменить токен бота.

## 7. Осознанные отличия от ТЗ
- SQLite вместо PostgreSQL — людей немного, один процесс.
- Суммы — целые рубли во всём журнале, не Decimal.
- Отдельной очереди уведомлений нет: бот и API в одном процессе, уведомления уходят в фоне.
- Решения по нарушениям графика — в Mini App (нужны комментарий и файлы); бот присылает сводку и итоговые сообщения.
